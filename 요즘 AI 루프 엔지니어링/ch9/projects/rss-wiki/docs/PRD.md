# rss-wiki PRD

- 작성일: 2026-09-17
- 상태: 초안 v1

## 1. 개요

RSS 피드에서 새 글을 직접 수집하고, 원문 본문을 추출해 Claude Code CLI로 한국어 요약을 만든 뒤, 마크다운 위키 파일로 정리해 주는 개인용 로컬 도구.

### 목표

- 구독한 피드의 새 글을 명령 한 번으로 수집/요약/정리한다.
- 결과를 Obsidian 같은 마크다운 도구로 바로 열어 읽을 수 있게 한다.
- 같은 글을 두 번 요약하지 않는다.

### 비목표

- 멀티유저, 인증, 권한 관리
- 웹 UI
- 상시 실행 서버, 자동 스케줄 실행
- 기존 RSS 리더(Miniflux, Feedly 등) API 연동
- OPML 가져오기

## 3. 사용자 시나리오

1. 사용자가 `feeds.yaml`에 구독할 피드 URL을 추가한다.
2. 사용자가 `rss-wiki run`을 실행한다.
3. 도구가 모든 피드를 읽어 새 글을 SQLite에 등록한다.
4. 새 글마다 원문 본문을 추출하고 `claude -p`로 요약을 만든다.
5. 요약 결과를 글별 마크다운 파일로 쓰고, 태그별 주제 페이지를 갱신한다.
6. 실행이 끝나면 새 글 수 / 요약 성공 수 / 실패 수를 터미널에 출력한다.
7. 사용자는 위키 폴더를 Obsidian으로 열어 읽는다.

## 4. 핵심 기능

### 4.1 피드 설정

- `feeds.yaml`에 피드 목록을 적는다.
- 피드별 필드: `url`(필수), `name`(선택, 없으면 피드 title 사용)
- 설정 파일에서 빠진 피드는 수집 대상에서 제외한다. 이미 만든 위키 파일은 지우지 않는다.

### 4.2 수집

- 각 피드를 HTTP로 가져와 파싱한다(RSS 2.0 / Atom).
- 글 식별 키: 피드 항목의 `guid`/`id`, 없으면 `link`.
- 이미 DB에 있는 글은 건너뛴다.
- 첫 실행 시 피드당 최근 10개만 등록하고 나머지는 등록하지 않는다. 이후 실행에서 등록하지 않았던 오래된 글이 새 글로 다시 잡히지 않아야 한다. (자체 결정: 합의)
- 첫 수집에서 상한 밖으로 등록하지 않은 글은 식별 키만 `skipped_keys` 테이블에 기록한다. 새 글 판정은 `articles`와 `skipped_keys` 어디에도 없는 키다. `articles`에는 등록하지 않는다. (자체 결정: 합의)

### 4.3 본문 추출

- 글 `link`를 열어 본문 텍스트를 추출한다.
- 추출 실패 또는 본문이 너무 짧으면 피드의 content / summary를 사용한다.
- 둘 다 없으면 해당 글은 요약 실패로 기록한다.
- 요약 입력으로 넘기는 본문은 앞부분 20,000자로 자른다. DB에는 원문 전체를 저장한다. (자체 결정: 합의)

### 4.4 요약

- `claude -p`를 서브프로세스로 호출해 요약한다.
- 원문 언어와 무관하게 한국어로 작성한다.
- 출력은 파싱 가능한 구조(JSON)로 받는다. 필드:
  - `summary`: 3줄 요약 (문자열 3개)
  - `key_points`: 핵심 포인트 목록
  - `tags`: 주제 태그 목록
- 출력이 형식에 맞지 않으면 요약 실패로 처리한다.
- 호출 옵션: 모델은 지정하지 않고(CLI 기본값), 호출당 타임아웃 180초, 글마다 순차 호출한다. (자체 결정: 합의)
- 태그 정규화: DB의 기존 태그 목록을 프롬프트에 넣어 재사용을 유도하고 새 태그도 허용한다. 저장 전 소문자화, 앞뒤 공백 제거, 내부 공백을 `-`로 치환한다. (자체 결정: 합의)
- 한 실행당 요약은 최대 20개. `rss-wiki run --max-summaries N`으로 바꿀 수 있고, 남은 글은 다음 실행에 처리한다. (자체 결정: 합의)

### 4.5 위키 생성

- 글별 파일: 피드별 폴더 아래 요약 마크다운 1개.
  - frontmatter: 제목, 원문 링크, 피드 이름, 발행일, 수집일, 태그
  - 본문: 3줄 요약, 핵심 포인트, 원문 링크
  - 파일 이름: `YYYY-MM-DD-slug.md` (발행일, 없으면 수집일). slug는 한글/영문/숫자를 유지하고 나머지는 `-`로 치환, 최대 80자. 충돌 시 `-2`, `-3` 접미사를 붙이며, 같은 DB로 다시 만들면 같은 이름이 나와야 한다. (자체 결정: 합의)
- 주제 페이지: 태그 하나당 마크다운 1개. 해당 태그가 붙은 글 링크를 최신순으로 나열한다.
- 주제 페이지 파일은 위키 루트의 `tags/` 폴더 아래 `{태그 slug}.md`로 둔다. 서로 다른 태그의 slug가 겹치면 `-2`, `-3` 접미사를 붙인다. (자체 결정)
- 주제 페이지는 DB 기준으로 매 실행 시 다시 생성한다(수동 편집 내용은 보존하지 않음).
- 어떤 글에도 붙어 있지 않게 된 태그의 낡은 주제 페이지는 지우지 않고 그대로 남긴다. 인덱스에서는 빠지므로 목록에는 나타나지 않는다. (자체 결정: PRD 4.1의 "이미 만든 위키 파일은 지우지 않는다"를 따르고, 파일을 지우는 동작은 잘못 판단했을 때 되돌릴 수 없어 넣지 않는다)
- 최신순의 기준 시각은 `published_at`이고, 없거나 파싱할 수 없거나 시간대 오프셋이 없으면 `created_at`을 쓴다. 둘 다 쓸 수 없는 글은 맨 뒤에 둔다. (자체 결정)
- 인덱스 페이지: 위키 루트에 `index.md` 하나. 피드별 최근 글 목록과 전체 태그(주제 페이지) 목록을 담고 매 실행 시 재생성한다. (자체 결정: 합의)
- 인덱스의 피드별 최근 글은 피드당 20개까지 싣는다. (자체 결정)

### 4.6 CLI

- `rss-wiki run`: 수집 → 본문 추출 → 요약 → 위키 생성 전체 실행
- 실행 결과 요약(새 글 / 성공 / 실패 / 포기)을 터미널에 출력한다.

## 5. 데이터 저장

### SQLite

- `feeds`: 피드 URL, 이름, 마지막 수집 시각, 연속 실패 횟수, 마지막 오류
- `articles`: 피드 참조, 식별 키, 제목, 링크, 발행일, 본문, 상태(pending / summarized / failed / given_up), 실패 횟수, 마지막 오류
- `summaries`: 글 참조, 3줄 요약, 핵심 포인트, 생성 시각
- `tags`, `article_tags`: 태그와 글 연결
- `skipped_keys`: 피드 참조, 식별 키, 기록 시각. (피드, 식별 키)가 기본 키. 첫 수집에서 등록하지 않은 글의 재등장 방지용. 이 테이블 추가로 스키마 버전(`user_version`)은 2다. (자체 결정: 합의)
- 시각 형식: 모든 시각 컬럼(`published_at`, 수집 시각, `last_fetched_at`, 요약 생성 시각)은 앱이 로컬 시간대 오프셋을 포함한 ISO8601(`2026-09-18T00:13:02+09:00`)로 넣는다. `DEFAULT CURRENT_TIMESTAMP`는 쓰지 않는다. `published_at`은 수집 시점에 로컬 시간대로 변환해 저장하고, 4.5의 파일 이름 날짜는 저장된 값의 날짜 부분을 그대로 쓴다. (자체 결정: 합의)

### 파일

- `feeds.yaml`: 구독 목록 (사용자 편집)
- SQLite DB 파일: 상태의 원천
- 위키 폴더: 산출물. DB로부터 다시 만들 수 있어야 한다.
- 경로: `feeds.yaml`의 최상위 설정 키 `wiki_dir`, `db_path`로 지정한다. 없으면 `./wiki`, `./data/rss-wiki.db`를 기본값으로 쓴다. (자체 결정: 합의)
- 상대 경로(기본값 포함)는 `feeds.yaml`이 있는 디렉터리를 기준으로 해석한다. (자체 결정)

## 6. 외부 연동

| 대상 | 용도 | 비고 |
| --- | --- | --- |
| RSS/Atom 피드 URL | 글 목록 수집 | HTTP GET |
| 원문 웹페이지 | 본문 추출 | HTTP GET |
| Claude Code CLI | 요약 생성 | 로컬에 `claude` 설치/로그인 필요, 구독 한도 사용 |

## 7. 실패 정책

- 실패 단위는 피드 하나 또는 글 하나. 한 항목의 실패가 전체 실행을 멈추지 않는다.
- 실패 시 오류 메시지와 실패 횟수를 DB에 기록한다.
- 다음 실행에서 실패 항목을 다시 시도한다.
- 연속 실패가 N회에 도달하면 `given_up` 상태로 바꾸고 더 시도하지 않는다.
- 포기 기준 N은 3회 고정(코드 상수)이다. 설정으로 바꾸지 않는다. (자체 결정: 합의)
- 실패 유형별 처리:
  - 피드 요청/파싱 실패: 피드 연속 실패 횟수 증가
  - 본문 추출 실패: 피드 content로 대체, 둘 다 없으면 글 실패
  - `claude` 호출 실패 / 타임아웃 / 출력 형식 오류: 글 실패
- `claude` 명령이 없거나 로그인되지 않은 경우: 요약 단계 시작 전에 확인하고 명확한 오류로 종료한다. (글 실패 횟수를 올리지 않는다.)
