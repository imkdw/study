코드 채점 평가: 분류 태스크

집합(set) 비교로 멀티라벨 분류 프롬프트를 평가합니다.

원본: 04_code_graded_classification_evals.ipynb

레슨

조금 더 현실적인 평가를 만듭니다. 고객 불만을 다음 카테고리로 분류하는 프롬프트입니다:

  • Software Bug
  • Hardware Malfunction
  • User Error
  • Feature Request
  • Service Outage

일부 불만은 두 개 카테고리에 걸칠 수 있습니다 ("설치를 잘못해서 컴퓨터가 안 켜짐" → User Error + Hardware Malfunction).

평가 데이터셋

const evalData = [
  { complaint: "The app crashes every time I try to upload a photo",
    goldenAnswer: ["Software Bug"] },
  { complaint: "My printer isn't recognized by my computer",
    goldenAnswer: ["Hardware Malfunction"] },
  { complaint: "I can't figure out how to change my password",
    goldenAnswer: ["User Error"] },
  { complaint: "The website is completely down, I can't access any pages",
    goldenAnswer: ["Service Outage"] },
  { complaint: "It would be great if the app had a dark mode option",
    goldenAnswer: ["Feature Request"] },
  { complaint: "The app is crashing and my phone is overheating",
    goldenAnswer: ["Software Bug", "Hardware Malfunction"] },
  { complaint: "I think I installed something incorrectly, now my computer won't start at all",
    goldenAnswer: ["User Error", "Hardware Malfunction"] },
  { complaint: "Your service is down, and I urgently need a feature to batch process files",
    goldenAnswer: ["Service Outage", "Feature Request"] },
  // ... 실습에서는 최소 20개, 실전에서는 100개 이상
];

초기 프롬프트

function basicPrompt(complaint: string) {
  return `Classify the following customer complaint into one or more of these
categories: Software Bug, Hardware Malfunction, User Error, Feature Request,
or Service Outage. Only respond with the matching category or categories and
nothing else.

Complaint: ${complaint}

Classification:`;
}

평가 로직 — 집합 비교

이번에는 정확 일치가 아닙니다. 출력을 쉼표로 나눠 Set으로 만들고 정답 집합과 비교합니다. 순서가 달라도 정답으로 인정됩니다:

async function getModelResponse(prompt: string) {
  const response = await ai.models.generateContent({
    model: "gemini-3.6-flash",
    contents: prompt,
    config: { maxOutputTokens: 200, temperature: 0 },
  });
  return response.text ?? "";
}

function calculateAccuracy(
  data: typeof evalData,
  responses: string[],
): number {
  let correct = 0;
  for (const [i, item] of data.entries()) {
    const golden = new Set(item.goldenAnswer.map((c) => c.toLowerCase()));
    const predicted = new Set(
      responses[i].split(/[,\n]/).map((c) => c.trim().toLowerCase()).filter(Boolean),
    );
    if (golden.size === predicted.size && [...golden].every((c) => predicted.has(c))) {
      correct++;
    }
  }
  return correct / data.length;
}

async function evaluatePrompt(promptFn: (c: string) => string) {
  const responses = await Promise.all(
    evalData.map((item) => getModelResponse(promptFn(item.complaint))),
  );
  const accuracy = calculateAccuracy(evalData, responses);
  console.log(`Accuracy: ${(accuracy * 100).toFixed(1)}%`);
  for (const [i, item] of evalData.entries()) {
    console.log(`Complaint: ${item.complaint}`);
    console.log(`Golden: ${item.goldenAnswer} | Response: ${responses[i]}\n`);
  }
  return accuracy;
}

await evaluatePrompt(basicPrompt);  // 원본 결과: 85%

개선 프롬프트 — 카테고리 정의 + 예시

function improvedPrompt(complaint: string) {
  return `You are an AI assistant specializing in customer support issue
classification. Your task is to analyze customer complaints and categorize them
into one or more of the following categories:

1. Software Bug: Issues related to software not functioning as intended.
2. Hardware Malfunction: Problems with physical devices or components.
3. User Error: Difficulties arising from user misunderstanding or misuse.
4. Feature Request: Suggestions for new functionalities or improvements.
5. Service Outage: System-wide issues affecting service availability.

Important Guidelines:
- A complaint may fall into multiple categories. If so, list all that apply but
  try to prioritize picking a single category when possible.

Examples:
1. Complaint: "The app crashes when I try to save my progress."
   Classification: Software Bug
2. Complaint: "My keyboard isn't working after I spilled coffee on it."
   Classification: Hardware Malfunction
3. Complaint: "I can't find the login button on your website."
   Classification: User Error
4. Complaint: "It would be great if your app had a dark mode."
   Classification: Feature Request
5. Complaint: "None of your services are loading for me or my colleagues."
   Classification: Service Outage
6. Complaint: "The app is acting buggy on my phone and it seems like your website
   is down, so I'm completely stuck!"
   Classification: Software Bug, Service Outage

Now, please classify the following customer complaint:

<complaint>${complaint}</complaint>

Only respond with the appropriate categories and nothing else.
Classification:`;
}

await evaluatePrompt(improvedPrompt);  // 원본 결과: 100%
핵심 교훈

정확 일치가 불가능한 태스크에서는 집합 비교 같은 유연한 채점 로직이 필요합니다. 카테고리 정의를 명시하고 멀티라벨 예시를 포함시킨 것이 85% → 100% 개선의 핵심이었습니다.

주의

이 평가는 단순하고 데이터셋이 작습니다. 프로세스를 보여주기 위한 예시이며 프로덕션급 평가의 표준은 아닙니다. 수작업 평가 로직은 금방 번거로워지므로 다음 레슨부터 전용 도구(promptfoo)를 소개합니다.

연습 4.1 — 부분 점수

현재 채점은 "전부 맞거나 0점"입니다. 정답의 일부만 맞힌 경우 부분 점수를 주는 버전(intersection / union 기반 F1 스코어)으로 calculateAccuracy를 수정해 보세요.

힌트 
const intersection = [...golden].filter((c) => predicted.has(c)).length;
const precision = intersection / predicted.size;
const recall = intersection / golden.size;
const f1 = precision + recall === 0 ? 0 : (2 * precision * recall) / (precision + recall);
