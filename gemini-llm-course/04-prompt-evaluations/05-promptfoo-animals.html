promptfoo 입문

전용 평가 도구로 프롬프트와 모델을 나란히 비교합니다.

원본: 05_prompt_foo_code_graded_animals/lesson.ipynb

레슨

직접 평가 로직을 짜는 건 금방 번거로워집니다. 오픈소스 도구 promptfoo는 여러 프롬프트/모델/프로바이더를 한 번에 평가하고 결과를 시각화해 줍니다.

Gemini에서 promptfoo

원본은 Anthropic 모델(anthropic:messages:...)을 쓰지만, promptfoo는 Google AI Studio provider를 지원합니다. google:gemini-3.6-flash 형태로 지정하고 GEMINI_API_KEY(또는 GOOGLE_API_KEY) 환경 변수를 설정하면 됩니다.

설치와 초기화

npx promptfoo@latest init

promptfooconfig.yaml이 생성됩니다. 여기에 프로바이더, 프롬프트, 테스트를 설정합니다.

프로바이더 설정

# promptfooconfig.yaml
description: "Animal Legs Eval"

providers:
  - "google:gemini-3.6-flash"
export GEMINI_API_KEY=your_api_key_here

프롬프트 지정

원본은 Python 함수를 쓰지만, JS 파일도 지원합니다. prompts.js를 만듭니다:

// prompts.js — 각 함수는 변수를 받아 최종 프롬프트 문자열을 반환
module.exports = {
  simplePrompt({ vars }) {
    return `You will be provided a statement about an animal and your job is to
determine how many legs that animal has.

Here is the animal statement.
<animal_statement>${vars.animal_statement}</animal_statement>

How many legs does the animal have? Please respond with a number`;
  },
  betterPrompt({ vars }) {
    return `You will be provided a statement about an animal and your job is to
determine how many legs that animal has.

Here is the animal statement.
<animal_statement>${vars.animal_statement}</animal_statement>

How many legs does the animal have? Please only respond with a single digit
like 2 or 9`;
  },
};
description: "Animal Legs Eval"

prompts:
  - file://prompts.js:simplePrompt
  - file://prompts.js:betterPrompt

providers:
  - "google:gemini-3.6-flash"

실행과 결과 보기

npx promptfoo@latest eval    # 평가 실행
npx promptfoo@latest view    # 브라우저 대시보드

각 프롬프트가 컬럼으로 나열되고 테스트별 통과/실패가 한눈에 보입니다. simple_prompt은 형식 문제로 전부 실패하고, better_prompt는 대부분 통과하지만 까다로운 추론 문제에서 실패합니다.

세 번째 프롬프트 + transform

CoT 프롬프트를 추가합니다:

  chainOfThoughtPrompt({ vars }) {
    return `...thinking step by step inside of <thinking> tags.
Then, output your final answer inside of <answer> tags...`;
  },

이 프롬프트의 출력에는 태그가 섞여 있으므로 <answer> 안의 값만 뽑는 transform이 필요합니다. transform.js:

// transform.js
module.exports = (output, context) => {
  const match = output.match(/<answer>([\s\S]*?)<\/answer>/);
  return match ? match[1].trim() : output;
};
defaultTest:
  options:
    transform: file://transform.js

모델 비교

프로바이더를 두 개 나열하면 같은 평가를 두 모델로 실행합니다:

providers:
  - google:gemini-3.6-flash
  - google:gemini-2.5-pro

어느 프롬프트가 좋은지뿐 아니라 어느 모델+프롬프트 조합이 이 태스크에 최적인지 알 수 있습니다.

재미있는 함정

원본에서 더 똑똑한 모델(Sonnet)이 오히려 CoT 프롬프트에서 하나를 틀렸습니다. "문어는 엄밀히 다리가 아니라 팔(arms)이다"라고 지나치게 똑똑하게 추론했기 때문입니다. "다리"의 정의를 프롬프트에 명시해야 모든 모델에서 안정적입니다.
