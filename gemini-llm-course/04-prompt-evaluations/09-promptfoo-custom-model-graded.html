커스텀 모델 채점 평가

내 grader 안에서 Gemini를 직접 호출해 정교한 루브릭 채점을 구현합니다.

원본: 09_custom_model_graded_prompt_foo/lesson.ipynb

레슨

태스크: 긴 Wikipedia 문서를 초등학생 수준의 짧은 요약으로 만드는 프롬프트 평가. llm-rubric은 단일 기준 판정에는 좋지만, 세부 루브릭(여러 항목 점수화, 평균 계산)이 필요하면 커스텀 grader 안에서 LLM을 직접 호출합니다.

프롬프트들 (prompts.js)

module.exports = {
  basicSummarize({ vars }) {
    return `Summarize this article ${vars.article}`;
  },
  betterSummarize({ vars }) {
    return `Summarize this article for a grade-school audience: ${vars.article}`;
  },
  bestSummarize({ vars }) {
    return `You are tasked with summarizing long wikipedia articles for a
grade-school audience. Write a short summary, keeping it as concise as possible.
The summary is intended for a non-technical, grade-school audience.
This is the article: ${vars.article}`;
  },
};

설정 파일

description: 'Summarization Evaluation'

prompts:
  - file://prompts.js:basicSummarize
  - file://prompts.js:betterSummarize
  - file://prompts.js:bestSummarize

providers:
  - id: google:gemini-3.6-flash
    label: "Gemini Flash"

tests:
  - vars:
      article: file://articles/article1.txt
  - vars:
      article: file://articles/article2.txt
  # ... article3~8

defaultTest:
  assert:
    - type: javascript
      value: file://custom_llm_eval.js

커스텀 모델 grader (custom_llm_eval.js)

grader 안에서 Gemini를 호출해 루브릭 점수를 매깁니다:

// custom_llm_eval.js
const { GoogleGenAI } = require("@google/genai");

const ai = new GoogleGenAI({});

const RUBRIC = `You are evaluating a summary of a Wikipedia article written for
a grade-school audience. Score the summary on these criteria (1-5 each):

1. Accuracy: Does the summary contain only facts from the article?
2. Conciseness: Is it appropriately short?
3. Readability: Can a grade-school student understand it?
4. Tone: Is it neutral and encyclopedic?

Return ONLY a JSON object:
{"accuracy": N, "conciseness": N, "readability": N, "tone": N, "explanation": "..."}

<article>
{{ARTICLE}}
</article>

<summary>
{{SUMMARY}}
</summary>`;

async function llmEval(summary, article) {
  const res = await ai.models.generateContent({
    model: "gemini-3.6-flash",
    contents: RUBRIC.replace("{{ARTICLE}}", article).replace("{{SUMMARY}}", summary),
    config: { responseMimeType: "application/json", temperature: 0 },
  });
  const parsed = JSON.parse(res.text ?? "{}");
  const scores = [parsed.accuracy, parsed.conciseness, parsed.readability, parsed.tone];
  const avg = scores.reduce((a, b) => a + b, 0) / scores.length;
  return { avg, explanation: parsed.explanation ?? "" };
}

module.exports = async (output, context) => {
  const article = context.vars.article;
  const { avg, explanation } = await llmEval(output, article);
  const threshold = 4.5;
  return {
    pass: avg >= threshold,
    score: avg,
    reason: explanation,
  };
};

구조 정리:

  • module.exports가 promptfoo가 호출하는 진입점 (원본의 get_assert에 해당)
  • 루브릭 프롬프트로 채점용 Gemini 호출 → JSON 점수 파싱 → 평균 계산
  • 임계값(4.5) 이상이면 pass. 점수와 이유를 함께 반환
npx promptfoo@latest eval   # 생성 + 채점 호출이라 시간이 더 걸림
npx promptfoo@latest view   # 대시보드에서 점수 분포와 이유 확인
JSON 강제 응답

채점 결과를 JSON으로 받기 위해 responseMimeType: "application/json"을 씁니다. 프롬프트에 "ONLY a JSON object"를 명시하는 것과 함께 쓰면 파싱이 안정적입니다.

비용과 일관성

테스트마다 생성 호출 + 채점 호출이 발생합니다. 3개 프롬프트 × 8개 테스트 = 24회 생성, 각각 채점 호출까지 48회의 API 호출입니다. 채점 모델의 비결정성을 줄이려면 temperature: 0을 설정하세요.
