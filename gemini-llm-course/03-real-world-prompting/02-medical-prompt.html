실전 프롬프트: 의료 기록 요약기

모호한 프롬프트를 단계별로 개선하며 모든 기법을 한 번에 적용합니다.

원본: 02_medical_prompt.ipynb

레슨

목표: 긴 환자 의료 기록을 받아, 의사가 다음 진료 전에 빠르게 훑어볼 수 있는 요약을 생성하는 프롬프트를 만듭니다.

입력 데이터 예시:

const record = `Patient Name: Evelyn Thompson
Age: 78
Medical Record:

1985: Diagnosed with type 2 diabetes, started on metformin
1992: Developed hypertension, prescribed lisinopril
1998: Total hip replacement (right) due to osteoarthritis
2000: Diagnosed with hypothyroidism, started on levothyroxine
2005: Admitted for atrial fibrillation, started on warfarin
2011: Admitted for transient ischemic attack (TIA), added aspirin
2015: Developed chronic kidney disease (CKD) stage 3
2023: Mobility declining, started physical therapy`;

원하는 출력에는 다음이 포함되어야 합니다: 환자 이름, 나이, 주요 진단 목록, 처방 약물, 최근 우려 사항, 의사를 위한 액션 아이템.

초기 "나쁜" 프롬프트

const badPrompt = `I have this patient medical record. Can you summarize it for me?

${record}

I need this for a quick review before the patient's appointment tomorrow.`;

이 프롬프트는 실행될 때마다 다른 형식의 요약을 만듭니다. 구조도, 필드도, 길이도 불명입니다.

개선 1: System Instruction 추가

시스템 지시에는 역할과 맥락만 넣습니다. 여기서는 "긴 환자 기록을 간결한 요약으로 바꾸는 의료 전문가"라는 역할입니다.

const system = `You are a highly experienced medical professional with a specialty
in translating complex patient histories into concise, actionable summaries.
Your role is to analyze patient records, identify critical information, and
present it in a clear, structured format that aids in diagnosis and treatment
planning. Your summaries are invaluable for busy healthcare providers who need
quick insights into a patient's medical history before appointments.`;

개선 2: 입력 데이터를 XML 태그로 구조화

const prompt = `<patient_record>
${record}
</patient_record>`;

이 작은 추가만으로 모델이 어디까지가 입력 데이터인지 정확히 인식합니다.

개선 3: 명확한 지시사항

const prompt = `I need your help summarizing patient medical records for our team
of doctors. We have a series of follow-up appointments tomorrow, and the doctors
need quick, insightful summaries to prepare.

Each summary should include the following elements in this order:
- The patient's name
- The patient's age
- A bulleted list of key diagnoses in chronological order
- A bulleted list of medications the patient is prescribed
- A bulleted list of other treatments: non-medication treatments like CBT or physical therapy
- A short bulleted list of recent concerns
- A bulleted list of key action items to help our doctors prepare

<patient_record>
${record}
</patient_record>`;

개선 4: 예시 추가

형식이 엄격한 출력에는 예시가 가장 효과적입니다. 이상적인 입출력 쌍을 <example> 안에 넣습니다:

const example = `Here's an example of how we'd like the summaries formatted:

<example>
<patient_record>
Patient Name: Ethan Blackwood
Age: 55
Medical Record:
2010: Annual check-up, mild hypertension noted
2012: Diagnosed with moderate depression following job loss
  - Started on sertraline and cognitive-behavioral therapy (CBT)
...
</patient_record>

<summary>
Name: Ethan Blackwood
Age: 55

Key Diagnoses:
- Hypertension (2010)
- Depression (2012)
...
</summary>
</example>`;

예시 출력을 <summary> 태그로 감싸면, 실제 출력도 같은 태그로 나옵니다. 이후 코드에서 태그 안 내용만 추출하면 됩니다.

최종 조합

const response = await ai.models.generateContent({
  model: "gemini-3.6-flash",
  contents: [{ role: "user", parts: [{ text: fullPrompt }] }],
  config: {
    systemInstruction: system,
    temperature: 0,
  },
});

보너스: JSON 출력으로 전환

프로그램에서 파싱하려면 JSON이 편합니다. 프롬프트에 JSON 스키마를 명시하고 예시도 JSON으로 바꾸면 됩니다:

const jsonPrompt = `Please provide these summaries in JSON format with the following structure:
{
  "name": "Patient's full name",
  "age": patient's age as an integer,
  "key_diagnoses": [{"diagnosis": "...", "year": 1985}],
  "medications": [{"name": "...", "purpose": "..."}],
  "other_treatments": [{"treatment": "...", "purpose": "..."}],
  "recent_concerns": ["..."],
  "action_items": ["..."]
}

<patient_record>
${record}
</patient_record>`;
Gemini에서 JSON 강제하기

원본은 "진짜 JSON 강제는 tool use로 한다"고 안내합니다. Gemini에서는 더 직접적인 방법이 있습니다: config.responseMimeType = "application/json"과 config.responseSchema를 쓰면 스키마 준수 JSON이 보장됩니다. 자세한 것은 코스 5에서 다룹니다.
