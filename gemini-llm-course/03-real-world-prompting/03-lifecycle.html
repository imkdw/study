프롬프트 엔지니어링이란

기법 나열이 아닌, 체계적인 개선 워크플로를 배웁니다.

원본: 03_prompt_engineering.ipynb

레슨

프롬프트 엔지니어링은 LLM이 원하는 출력을 내도록 지시를 설계/개선/최적화하는 기술이자 과학입니다. 단순히 질문을 던지는 "기본 프롬프팅"과는 다릅니다.

기본 프롬프팅과의 차이

구분기본 프롬프팅프롬프트 엔지니어링
복잡도단일 턴, 단순 질의멀티턴, 복잡한 지시, 구조화된 입출력
정밀도모호해도 일회용이면 OK오해 여지 없는 정확한 지시 (프로덕션 필수)
개선 방식일회성체계적 테스트, 분석, 반복 개선
확장성특정 입력에만 동작다양한 입력과 엣지 케이스를 커버

핵심은 반복 가능성(repeatability)입니다. 운 좋게 한 번 잘 된 프롬프트가 아니라, 어떤 입력이 와도 일관되게 동작하는 프롬프트를 만드는 것이 목표입니다.

프롬프트 엔지니어링 생애주기

빈 페이지에서 완벽한 프롬프트가 한 번에 나오지 않습니다. 다음 5단계를 반복합니다:

  1. 초기 프롬프트 작성
  2. 테스트와 문제 식별
  3. 적절한 기법 선택
  4. 개선 구현
  5. 반복과 정제

1. 초기 프롬프트 작성

목표를 명확히 하는 초안을 씁니다. 이미 배운 기법(명확한 지시, 구조화)을 넣으면 좋지만, 최종본은 초안과 전혀 다르게 될 가능성이 높다고 가정하세요.

2. 테스트와 문제 식별

다양한 입력으로 테스트합니다 (평가는 코스 4에서 자세히 다룹니다):

  • 테스트 케이스 준비: 정상 케이스 + 엣지 케이스를 커버하는 입력 세트
  • 실행: 같은 프롬프트로 모든 케이스 실행
  • 채점: 코드, 사람, 또는 LLM으로 응답 평가

주요 지표: 정확성(accuracy), 일관성(consistency), 완전성(completeness), 지시 준수(instruction adherence).

3. 적절한 기법 선택

문제를 발견했으면 무작정 고치지 말고 다음 순서를 따릅니다:

  1. 근본 원인 진단: 왜 이 문제가 발생하는가?
  2. 해결책 탐색: 진단에 맞는 프롬프팅 기법은?
  3. 기법 선택: 가장 유망한 것부터 적용

4. 개선 구현

선택한 기법을 프롬프트에 적용합니다. 여러 변경을 할 때는 한 번에 하나씩 적용해서 각 변경의 효과를 분리해서 파악하는 것이 좋습니다.

5. 반복과 정제

  • 같은 테스트 케이스로 재테스트
  • 결과 비교: 목표한 문제가 해결됐는가?
  • 새로운 문제가 생겼는지 확인 (회귀)
  • 만족할 때까지 사이클 반복
3-2장과의 관계

이전 레슨(의료 기록)은 모든 기법을 "산탄총"처럼 한 번에 쏜 예시입니다. 실제 프로덕션에서는 이 레슨의 생애주기를 따라 문제를 진단하고 필요한 기법만 적용하는 것이 더 효율적이고 디버깅도 쉽습니다.
