핵심 프롬프팅 기법 복습

코스 2에서 배운 기법들을 프로덕션 환경 관점으로 다시 정리합니다.

원본: 01_prompting_recap.ipynb

레슨

이 코스는 코스 2(Interactive Tutorial)를 마친 사람을 대상으로 합니다. 기초를 다시 설명하지 않고, 실제 서비스에 쓸 프롬프트를 만드는 데 각 기법이 왜 중요한지를 보여줍니다.

핵심 기법 목록

  1. 명확하고 직접적으로 (Be clear and direct)
  2. XML 태그로 프롬프트 구조화
  3. 예시 사용 (multishot / few-shot)
  4. 모델에게 생각할 공간 주기 (chain of thought)
  5. 역할 부여 (system instruction)
  6. 긴 컨텍스트 다루기 팁
프롬프트 생성기 활용

원본은 Anthropic Console의 Prompt Generator를 소개합니다. Gemini에는 대응하는 공식 도구가 없지만, 같은 효과를 낼 수 있습니다: "다음 태스크를 위한 고품질 프롬프트를 작성해줘"라고 Gemini에게 메타 프롬프트를 던지는 것입니다. 생성된 프롬프트는 출발점일 뿐이며, 반드시 직접 반복 개선해야 합니다.

1. 명확하고 직접적으로

가장 중요하면서 가장 단순한 기법입니다. 출력 형식, 길이, 스타일을 명시하고 모델이 맥락을 알고 있다고 가정하지 마세요.

나쁜 예: 고객 피드백 분석

// 모호함: 어떤 형식으로? 어느 정도 깊이로?
const badPrompt = `Here's some customer feedback. Can you tell me what people think?

${customerFeedback}`;

좋은 예: 같은 태스크를 구체화

const goodPrompt = `I need you to analyze this customer feedback for our recent software release:
<feedback>
${customerFeedback}
</feedback>

Please provide a detailed report with the following sections:

1. Summary (50-100 words): Concise overview of the general sentiment and main themes.
2. Feature Analysis:
   - List top 3 most praised features (bullet points)
   - List top 3 most criticized features (bullet points)
3. User Experience Issues:
   - List top 3 reported usability problems (bullet points)
   - For each issue, suggest a potential fix (in parentheses)
4. Sentiment Breakdown:
   - Positive: X%
   - Neutral: Y%
   - Negative: Z%
5. Actionable Insights (3-5 bullet points): Key takeaways and recommended actions.

Use XML tags to structure your response for easy parsing:
<summary></summary>
<feature_analysis></feature_analysis>
<ux_issues></ux_issues>
<sentiment></sentiment>
<insights></insights>`;
언제 쓰나

항상, 특히 복잡하거나 중요한 태스크. 특정 출력이 필요할 때, 여러 단계를 거치는 태스크일 때 필수입니다. 해결하는 문제: 지시 오해, 모호하거나 무관한 응답, 태스크 불완전 수행.

2. XML 태그로 구조화

입력 데이터, 지시사항, 예시를 XML 태그로 분리하면 모델이 프롬프트의 각 부분을 정확히 구분합니다. 출력도 태그로 감싸게 하면 파싱이 쉬워집니다.

const prompt = `<document>
${productDefectReport}
</document>

<instructions>
1. Identify the root cause of the defect described above.
2. Suggest 2-3 remediation steps.
3. Rate severity as LOW / MEDIUM / HIGH.
</instructions>

Put your analysis in <analysis> tags.`;

3. 예시 사용 (Multishot)

잘 만들어진 입출력 예시 2-3개는 어떤 지시 문장보다 강력합니다. 형식, 톤, 깊이를 한 번에 전달합니다.

const prompt = `Write a product announcement email in this style:

<example>
Subject: Meet Nova: notes that write themselves

Hi team,

Today we're launching Nova, our new AI note-taker...
[tone: enthusiastic but professional, 3 short paragraphs, one CTA button]
</example>

Now write an announcement email for: ${newFeature}`;

4. 생각할 공간 주기

복잡한 분석/추론 태스크에서는 "먼저 생각하고 답하라"고 지시하세요. <thinking> 태그에 분석을, 최종 답은 별도 태그에 두면 추론 과정을 검토할 수 있고 정확도도 올라갑니다.

const prompt = `Should we enter the European market with our product?
Consider the market data below.

<market_data>
${marketData}
</market_data>

First, analyze the pros and cons step by step in <thinking> tags.
Then give a final recommendation in <recommendation> tags.`;
Gemini 참고

Gemini 2.5 계열은 자체적인 thinking 기능을 가진 모델도 있지만, 프롬프트에서 명시적으로 <thinking> 출력을 요구하는 것은 여전히 유효합니다. 모델의 내부 추론과 별개로, 응답 안에 검토 가능한 근거를 남기기 때문입니다.

5. 역할 부여 (System Instruction)

원본에서는 system prompt로 역할을 부여합니다. Gemini에서는 config.systemInstruction에 넣습니다. 시스템 지시에는 역할과 맥락만 두는 것이 경험칙입니다.

const response = await ai.models.generateContent({
  model: "gemini-3.6-flash",
  contents: userPrompt,
  config: {
    systemInstruction: `You are a crisis communication expert for a SaaS company.
You respond to product incidents with calm, precise, customer-first messaging.`,
  },
});

6. 긴 컨텍스트 팁

  • 긴 문서는 프롬프트 맨 위에 두고, 지시는 문서 뒤에 둡니다.
  • 문서 인용을 먼저 요구하면 근거 기반 답변이 나옵니다.
  • 여러 문서는 각각 <document index="1"> 같은 태그로 구분합니다.
