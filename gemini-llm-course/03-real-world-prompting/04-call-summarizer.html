고객 지원 통화 기록 요약기

JSON 출력, 사고 공간, 엣지 케이스 처리를 조합해 프로덕션급 프롬프트를 만듭니다.

원본: 04_call_summarizer.ipynb

레슨

태스크: 고객 지원 통화 전사본(transcript)을 받아 구조화된 JSON 요약을 생성합니다. 요약에는 고객 이슈, 해결 방법, 후속 조치 필요 여부, 대화의 모호한 부분이 포함되어야 합니다.

1단계: 단순 프롬프트부터

const prompt = `Summarize the following customer service call transcript.
Focus on the main issue, how it was resolved, and any required follow-up.

${transcript}`;

async function summarizeCall(transcript: string) {
  const response = await ai.models.generateContent({
    model: "gemini-3.6-flash",
    contents: prompt.replace("${transcript}", transcript),
  });
  return response.text;
}

이 버전의 문제:

  • 출력 형식 미지정 → 요약마다 구조가 다름
  • 해결 안 된 케이스, 정보 부족 케이스 처리 지침 없음
  • 길이 제약 없음 → 과도하게 장황할 수 있음
  • 개인정보 제외 지시 없음 → 프라이버시 문제

2단계: System Instruction

const system = `You are an expert customer service analyst, skilled at extracting
key information from call transcripts and summarizing them in a structured format.
Your task is to analyze customer service call transcripts and generate concise,
accurate summaries while maintaining a professional tone.`;

3단계: 프롬프트 구조화

긴 문서(전사본)는 위에, 지시는 뒤에 둡니다. 프롬프트를 부분별로 나눠 작성합니다:

// 입력 데이터 부분
const promptPt1 = `Analyze the following customer service call transcript and
generate a JSON summary of the interaction:

<transcript>
${transcript}
</transcript>`;

출력 JSON 스키마를 먼저 설계합니다:

{
  "summary": {
    "customerIssue": "Brief description of the main problem",
    "resolution": "How the issue was addressed or resolved",
    "followUpRequired": true,
    "followUpDetails": "Follow-up actions, or null if none"
  },
  "status": "COMPLETE",
  "ambiguities": ["unclear points, or empty array"]
}
// 지시사항 부분
const promptPt2 = `Instructions:
1. Read the transcript carefully.
2. Analyze it, focusing on the main issue, resolution, and any follow-up required.
3. Generate a JSON object summarizing the key aspects of the interaction.

Important guidelines:
- Confidentiality: Omit all specific customer data like names, phone numbers, emails.
- Character limit: Restrict each text field to a maximum of 100 characters.
- Maintain a professional tone in your summary.

Output format:
Generate a JSON object with the following structure:
<json>
{ ...위 스키마... }
</json>`;

4단계: 사고 공간 + 출력 태그

JSON을 바로 내놓기 전에 <thinking> 태그에서 먼저 분석하게 합니다. 추론이 노출되어 디버깅이 쉽고, JSON 품질도 올라갑니다:

const promptPt3 = `Before generating the JSON, please analyze the transcript in
<thinking> tags. Include your identification of the main issue, resolution,
follow-up requirements, and any ambiguities.
Then, provide your JSON output in <json> tags.`;

5단계: 엣지 케이스 발견

정상 통화만 테스트하면 안 됩니다. 실제 데이터에는 이런 케이스가 섞여 있습니다:

  • 잘못 건 전화 (몇 마디 후 종료)
  • 불완전한 통화 (중간에 끊김, 정보 부족)
  • 음성이 깨진 전사본
  • 언어 장벽 (상담사가 고객 언어를 모름)

현재 프롬프트는 이런 케이스도 억지로 "COMPLETE" 요약을 만듭니다. 요약 통계를 오염시키므로 걸러내야 합니다.

6단계: 불충분 데이터 기준 추가

const insufficientData = `Insufficient data criteria:
If any of these conditions are met:
a) The transcript has fewer than 5 total exchanges
b) The customer's issue is unclear
c) The call is garbled, incomplete, or is hindered by a language barrier
Then return ONLY the following JSON:
{
  "status": "INSUFFICIENT_DATA"
}`;

7단계: 다양한 케이스의 예시 추가

예시는 세 가지 상황을 커버해야 합니다:

  1. 완결된 상호작용, 후속 조치 불필요
  2. 완결됐지만 후속 조치 필요 + 모호한 부분 있음
  3. 요약 불가 (INSUFFICIENT_DATA)

최종 프롬프트 조합

const prompt = `Analyze the following customer service call transcript and
generate a JSON summary of the interaction:

<transcript>
${transcript}
</transcript>

<instructions>
1. Read the transcript carefully.
2. Analyze it, focusing on the main issue, resolution, and follow-up.
3. Generate a JSON object per the specified structure.

Important guidelines:
- Confidentiality: Omit all specific customer data.
- Character limit: max 100 characters per text field.
- Maintain a professional tone.

Output format: JSON inside <json> tags.
{ ...스키마... }

Insufficient data criteria:
a) fewer than 5 exchanges, b) unclear issue, c) garbled/language barrier
→ return ONLY {"status": "INSUFFICIENT_DATA"}
</instructions>

<examples>
...3가지 케이스의 입출력 예시...
</examples>

Before generating the JSON, analyze the transcript in <thinking> tags.`;
핵심 교훈

좋은 구조화 출력 프롬프트 = 명확한 스키마 + 상태 필드 + 엣지 케이스 탈출구 + 다양한 예시 + 사고 공간. status: "INSUFFICIENT_DATA" 같은 명시적 퇴로를 만들어 두면 모델이 억지 요약을 생성하는 것을 막을 수 있습니다.

연습

연습 4.1 — 태그 추출

응답에서 <json> 태그 안의 내용만 추출하고 파싱하는 유틸리티를 작성해 보세요:

정답 예시 
function extractJson(text: string): unknown {
  const match = text.match(/<json>([\s\S]*?)<\/json>/);
  const raw = match ? match[1] : text;
  return JSON.parse(raw.trim());
}
