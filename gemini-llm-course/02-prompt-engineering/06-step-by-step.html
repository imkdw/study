단계별로 생각하기 (Chain-of-Thought)

모델에게 "생각할 시간"을 주면 정확도가 올라갑니다.

원본: 06_Precognition_Thinking_Step_by_Step.ipynb

레슨

누군가 자는 당신을 깨워 복잡한 질문에 바로 대답하라고 한다면 잘할 수 있을까요? 시간을 주고 생각을 정리하게 하는 편이 낫습니다. 모델도 마찬가지입니다.

단계별로 생각하게 하면 특히 복잡한 태스크에서 정확도가 올라갑니다. 단, 생각은 출력으로 나와야만 의미가 있습니다. "생각만 하고 답만 출력해"라고 하면 실제로는 아무 생각도 안 한 셈입니다.

예시: 영화 리뷰 감정 분석

아래 리뷰는 두 번째 문장이 첫 번째의 진정성을 의심하게 합니다(풍자). 그런데 모델은 "unrelated"를 문자 그대로 받아들입니다:

const PROMPT = `Is this movie review sentiment positive or negative?

This movie blew my mind with its freshness and originality. In totally unrelated news, I have been living under a rock since the year 1900.`;

답하기 전에 먼저 생각하게 고칩니다 — 처리 단계를 직접 명시하고 역할도 살짝 얹습니다:

const SYSTEM_PROMPT = "You are a savvy reader of movie reviews.";
const PROMPT = `Is this review sentiment positive or negative? First, write the best arguments for each side in <positive-argument> and <negative-argument> XML tags, then answer.

This movie blew my mind with its freshness and originality. In totally unrelated news, I have been living under a rock since 1900.`;
순서 민감성

모델은 때때로 항목 순서에 민감합니다. 위 예시에서 positive/negative 인자의 순서를 바꾸면 최종 판단이 바뀔 수 있습니다. 웹 학습 데이터에서 두 번째 선택지가 정답인 경우가 많았기 때문으로 추정됩니다. 양쪽 순서를 모두 테스트해 보세요.

예시: 사실 문제

// 그냥 물으면 틀릴 수 있음
const PROMPT = "Name a famous movie starring an actor who was born in the year 1956.";

// <brainstorm> 태그에서 먼저 생각하게 하면 정답률이 올라감
const PROMPT2 = "Name a famous movie starring an actor who was born in the year 1956. First brainstorm about some actors and their birth years in <brainstorm> tags, then give your answer.";
Gemini의 thinking 모드

Gemini 2.5 계열은 내부 "thinking"을 지원합니다. config.thinkingConfig로 켜면 모델이 내부 추론을 거칩니다. 그래도 명시적 "단계별 출력"은 근거를 눈으로 검증할 수 있다는 장점이 있어 여전히 유효한 기법입니다.

연습

이메일을 다음 카테고리로 분류하는 과제입니다:

  • (A) Pre-sale question
  • (B) Broken or defective item
  • (C) Billing question
  • (D) Other (please explain)
연습 6.1 — 이메일 분류

PROMPT를 수정해 모델이 올바른 분류만 출력하게 하세요. "(B) Broken or defective item"처럼 괄호 문자와 카테고리 이름을 모두 포함해야 합니다.

const PROMPT = `Please classify this email: {email}`;

const EMAILS = [
  "Hi -- My Mixmaster4000 is producing a strange noise when I operate it. It also smells a bit smoky and plasticky, like burning electronics. I need a replacement.",   // B
  "Can I use my Mixmaster 4000 to mix paint, or is it only meant for mixing food?",                                                                              // A or D
  "I HAVE BEEN WAITING 4 MONTHS FOR MY MONTHLY CHARGES TO END AFTER CANCELLING!! WTF IS GOING ON???",                                                            // C
  "How did I get here I am not good with computer. Halp.",                                                                                                       // D
];
const ANSWERS = [["B"], ["A", "D"], ["C"], ["D"]];
const REGEX: Record<string, RegExp> = {
  A: /A\) P/, B: /B\) B/, C: /C\) B/, D: /D\) O/,
};

for (const [i, email] of EMAILS.entries()) {
  const prompt = PROMPT.replace("{email}", email);
  const response = await getCompletion(prompt);
  const ok = ANSWERS[i].some((a) => REGEX[a].test(response));
  console.log(response, "| 통과:", ok);
}
힌트 보기

1) 카테고리 목록을 프롬프트에 포함시키세요(괄호 문자 포함, XML 태그로 감싸도 좋음). 2) "분류만 답해, 다른 말 없이"라고 하거나 prefill로 (를 넣어 서두를 없애세요. 3) 카테고리 전체 이름까지 포함하게 하세요. 4) {email} 플레이스홀더를 잊지 마세요.

(A) Pre-sale question

(C) Billing question
(D) Other (please explain)
</categories>`;

연습 6.2 — 형식 갖추기

위를 개선해 정답 문자만 <answer></answer> 태그로 감싸게 하세요. 예: 첫 이메일은 정확히 <answer>B</answer>를 포함해야 합니다.

힌트 보기

가장 간단한 방법은 원하는 출력 형식의 예시를 프롬프트에 넣는 것입니다 (<example> 태그 사용). prefill을 썼다면 prefill 부분은 응답에 포함되지 않음을 기억하세요.

정답 보기 
const PROMPT = `Please classify this email into the following categories: {email}

<categories>
(A) Pre-sale question
(B) Broken or defective item
(C) Billing question
(D) Other (please explain)
</categories>

Write the letter of the correct category in <answer> tags, like <example><answer>B</answer></example>.`;
