역할 부여 (Role Prompting)

모델에 특정 역할과 맥락을 입혀 응답의 톤과 정확도를 바꿉니다.

원본: 03_Assigning_Roles_Role_Prompting.ipynb

레슨

"모델은 맥락이 없다"는 주제에 이어, 때로는 모델이 특정 역할에 몰입하도록 만드는 게 중요합니다. 이것이 역할 프롬프팅입니다. 역할 맥락이 구체적일수록 좋습니다.

역할 부여는 글쓰기, 코딩, 요약 등 다양한 분야에서 성능을 높입니다. 사람이 "~처럼 생각해봐"라는 말로 도움받는 것과 같습니다. 응답의 스타일, 톤, 어조도 바뀝니다.

역할은 어디에?

역할 부여는 systemInstruction에 넣어도 되고 user 메시지 안에 포함해도 됩니다.

예시: 고양이 역할

역할 없이 물으면 평범한 답이 나옵니다:

await getCompletion("스케이트보드에 대해 한 문장으로 어떻게 생각해?");
// "스케이트보드는 재미있고 기술을 요구하는 스포츠입니다." 같은 평이한 답

같은 질문에 역할을 입히면 톤/스타일/내용이 역할에 맞게 바뀝니다:

const SYSTEM_PROMPT = "너는 고양이야.";
await getCompletion("스케이트보드에 대해 한 문장으로 어떻게 생각해?", SYSTEM_PROMPT);
// "그 시끄러운 바퀴 달린 판자? 내 낮잠을 방해하는 물건이야." 같은 답

보너스: 청중도 알려주면 더 정확해집니다. "너는 고양이야"와 "너는 스케이트보더 무리에게 말하는 고양이야"는 다른 답을 냅니다.

예시: 논리 문제

아래 문제의 정답은 "예(Yes)"입니다. 그런데 역할 없이 물으면 모델이 정보가 부족하다며 틀리게 답하는 경우가 있습니다:

const PROMPT =
  "Jack is looking at Anne. Anne is looking at George. " +
  "Jack is married, George is not, and we don't know if Anne is married. " +
  "Is a married person looking at an unmarried person?";

논리 봇 역할을 주면 정답을 맞힙니다:

const SYSTEM_PROMPT = "You are a logic bot designed to answer complex logic problems.";
await getCompletion(PROMPT, SYSTEM_PROMPT);
같은 결과를 내는 방법은 여러 개

이 코스를 통해 배우겠지만, 비슷한 결과를 내는 프롬프트 기법은 여럿입니다. 어떤 기법을 쓸지는 취향입니다. 직접 실험해서 자신만의 스타일을 찾으세요.

연습

연습 3.1 — 수학 채점

아래 방정식 풀이에는 두 번째 단계에 명백한 산수 오류가 있습니다(2x = 6이 아니라 12). 그런데 모델은 "맞다"고 채점하는 경우가 있습니다. PROMPT나 SYSTEM_PROMPT를 수정해 incorrect하게 채점하게 만드세요.

const SYSTEM_PROMPT = "";
const PROMPT = `Is this equation solved correctly below?

2x - 3 = 9
2x = 6
x = 3`;

const response = await getCompletion(PROMPT, SYSTEM_PROMPT);

function gradeExercise(text: string) {
  return /incorrect|not correct/i.test(text);
}
console.log(response);
console.log("통과:", gradeExercise(response));
힌트 보기

"incorrect" 또는 "not correct"가 포함되면 통과입니다. 수학 문제를 잘 풀 수 있는 역할을 부여해 보세요.

정답 보기 
const SYSTEM_PROMPT =
  "You are a meticulous math professor who checks each step of a solution " +
  "for arithmetic errors before judging it correct or incorrect.";
