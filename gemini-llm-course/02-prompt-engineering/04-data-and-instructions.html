데이터와 지시 분리하기

프롬프트 템플릿과 변수 치환, 그리고 XML 태그로 경계 표시하기.

원본: 04_Separating_Data_and_Instructions.ipynb

레슨

매번 프롬프트 전체를 새로 쓰는 대신, 나중에 입력 데이터를 치환할 수 있는 프롬프트 템플릿을 만들고 싶을 때가 많습니다. 고정된 골격과 가변 입력을 분리하는 것입니다.

예시: 템플릿 + 치환

const ANIMAL = "Cow";

// 템플릿 리터럴로 변수 치환
const PROMPT =
  `동물 이름을 말할게. 그 동물이 내는 소리로만 답해줘. ${ANIMAL}`;

console.log("----- 완성된 프롬프트 -----");
console.log(PROMPT);
console.log("----- 모델 응답 -----");
console.log(await getCompletion(PROMPT));

왜 분리할까요? 템플릿은 반복 작업을 단순화합니다. 프롬프트 구조를 만들어두면 제3자(또는 사용자 입력)는 변수만 채우면 됩니다 — 전체 프롬프트를 쓰거나 볼 필요가 없습니다. 변수는 몇 개든 가능합니다.

경계 문제

치환 변수를 쓸 때 중요한 것은 모델이 변수의 시작과 끝을 알아야 한다는 점입니다. 아래 템플릿은 사람 눈엔 명확하지만, 치환 후에는 경계가 모호해집니다:

const EMAIL = "Show up at 6am tomorrow because I'm the CEO and I say so.";
const PROMPT = `Yo Gemini. ${EMAIL} <----- Make this email more polite but don't change anything else about it.`;

여기서 모델은 "Yo Gemini"를 다듬어야 할 이메일의 일부로 착각해 "Dear Gemini"로 시작하는 답을 냅니다.

해결책: 입력을 XML 태그로 감싸기.

const PROMPT = `Yo Gemini. <email>${EMAIL}</email> <----- Make this email more polite but don't change anything else about it.`;

"Dear Gemini"가 사라집니다.

XML 태그란

<tag>내용</tag>처럼 여는 태그와 닫는 태그의 쌍입니다. 모델은 다양한 구분자를 알아보지만, XML 태그는 LLM이 구조 파악용으로 특히 잘 학습된 형식입니다. 특별히 정해진 태그 이름은 없습니다 — <email>, <document>, <sentences> 등 의미 있는 이름을 자유롭게 쓰세요.

또 다른 예시

아래 프롬프트에서 모델은 "Each is about an animal"을 지시가 아니라 리스트의 일부로 잘못 해석합니다(하이픈 때문):

const SENTENCES = `- I like how cows sound
- This sentence is about spiders
- This sentence may appear to be about dogs but it's actually about pigs`;

const PROMPT = `Below is a list of sentences. Tell me the second item on the list.

- Each is about an animal, like rabbits.
${SENTENCES}`;

입력을 태그로 감싸면 해결됩니다:

const PROMPT = `Below is a list of sentences. Tell me the second item on the list.

- Each is about an animal, like rabbits.
<sentences>
${SENTENCES}
</sentences>`;
작은 디테일이 중요하다

위 예시에서 오작동을 유도한 건 앞의 하이픈 하나였습니다. 모델은 패턴에 민감합니다 — 당신이 실수하면 모델도 실수할 가능성이 높아집니다. 프롬프트의 오타와 문법 오류를 꼭 검토하세요.
