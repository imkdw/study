스트리밍

응답이 생성되는 대로 받아오는 스트리밍의 원리와 사용법을 배웁니다.

원본: anthropics/courses — anthropic_api_fundamentals/05_Streaming.ipynb

학습 목표

  • 스트리밍이 어떻게 동작하는지 이해한다
  • 스트림 청크를 처리할 수 있다

왜 스트리밍인가

지금까지의 방식은 전체 응답이 완성된 뒤에야 결과를 받습니다. 긴 텍스트를 생성하면 사용자는 수십 초간 빈 화면을 봅니다.

스트리밍은 모델이 생성하는 즉시 조각(chunk)을 보내줍니다. Gemini 앱이나 ChatGPT에서 답변이 타자치듯 나오는 것이 이 방식입니다.

스트림 사용하기

generateContentStream을 호출하면 AsyncGenerator가 반환되고, for await로 청크를 순회합니다:

import { GoogleGenAI } from "@google/genai";

const ai = new GoogleGenAI({});

const stream = await ai.models.generateContentStream({
  model: "gemini-3.6-flash",
  contents: "세 단어로 된 문장을 써줘. 서두 없이 딱 세 단어만.",
});

for await (const chunk of stream) {
  console.log(chunk);
}

각 청크는 GenerateContentResponse와 같은 구조입니다. 텍스트는 chunk.text로 꺼냅니다:

for await (const chunk of stream) {
  process.stdout.write(chunk.text ?? "");   // 줄바꿈 없이 이어서 출력
}
// Cats meow loudly.
Claude와의 구조 차이

Claude는 message_start, content_block_delta 같은 세분화된 이벤트 타입을 스트리밍합니다. Gemini는 더 단순합니다: 매 청크가 동일한 응답 구조를 가지며 증분 텍스트를 담고 있습니다. 덕분에 처리 코드가 단순합니다.

토큰 사용량 확인

스트리밍에서는 마지막 청크에 usageMetadata가 들어옵니다:

let lastChunk;
for await (const chunk of stream) {
  process.stdout.write(chunk.text ?? "");
  lastChunk = chunk;
}
console.log(lastChunk?.usageMetadata);
// { promptTokenCount: 14, candidatesTokenCount: 258, totalTokenCount: 272 }

TTFT(Time To First Token)

스트리밍의 핵심 이점은 첫 토큰까지의 시간을 줄이는 것입니다. 비교 실험:

async function measureNonStreaming() {
  const start = performance.now();
  const response = await ai.models.generateContent({
    model: "gemini-3.6-flash",
    contents: "미국 독립혁명의 역사를 설명하는 긴 에세이를 써줘",
    config: { maxOutputTokens: 500 },
  });
  const total = (performance.now() - start) / 1000;
  console.log(`첫 토큰까지: ${total}초 (전체 완료와 동일)`);
  console.log(`생성 토큰: ${response.usageMetadata?.candidatesTokenCount}`);
}

async function measureStreaming() {
  const start = performance.now();
  const stream = await ai.models.generateContentStream({
    model: "gemini-3.6-flash",
    contents: "미국 독립혁명의 역사를 설명하는 긴 에세이를 써줘",
    config: { maxOutputTokens: 500 },
  });

  let ttft: number | undefined;
  let usage;
  for await (const chunk of stream) {
    if (ttft === undefined && chunk.text) {
      ttft = (performance.now() - start) / 1000;
    }
    usage = chunk.usageMetadata ?? usage;
  }
  const total = (performance.now() - start) / 1000;
  console.log(`첫 토큰까지: ${ttft}초`);
  console.log(`전체 완료까지: ${total}초`);
  console.log(`생성 토큰: ${usage?.candidatesTokenCount}`);
}

전형적인 결과: 비스트리밍은 첫 토큰이 4초, 스트리밍은 0.5초. 무거운 모델과 긴 출력일수록 격차가 커집니다(수십 초 → 1~2초).

스트리밍은 총 생성 시간을 줄이지 않는다

첫 데이터가 빨리 도착할 뿐, 마지막 토큰까지 걸리는 총 시간은 거의 같습니다. 체감 반응속도(UX)를 개선하는 기술입니다.

실습: 스트리밍 챗봇

1-2에서 만든 챗봇을 스트리밍 버전으로 업그레이드하세요. 응답이 생성되는 대로 출력되고, 완성된 텍스트는 대화 이력에 저장되어야 합니다.

정답 보기 
import { GoogleGenAI } from "@google/genai";
import readline from "node:readline";

const ai = new GoogleGenAI({});
const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
const question = (q: string) => new Promise<string>((res) => rl.question(q, res));

const history: { role: "user" | "model"; parts: { text: string }[] }[] = [];

while (true) {
  const input = await question("You: ");
  if (input.toLowerCase() === "quit") break;

  history.push({ role: "user", parts: [{ text: input }] });
  process.stdout.write("Gemini: ");

  const stream = await ai.models.generateContentStream({
    model: "gemini-3.6-flash",
    contents: history,
  });

  let reply = "";
  for await (const chunk of stream) {
    const text = chunk.text ?? "";
    process.stdout.write(text);
    reply += text;
  }
  console.log();

  history.push({ role: "model", parts: [{ text: reply }] });
}
rl.close();

Chats API로는 chat.sendMessageStream({ message })을 쓰면 이력 관리와 스트리밍이 한 번에 해결됩니다.
