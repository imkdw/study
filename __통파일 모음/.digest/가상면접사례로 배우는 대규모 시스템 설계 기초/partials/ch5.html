5-1

해시 키 재배치 문제

서버 한 대가 빠지면 % N의 결과가 전부 바뀐다.

핵심 hash(key) % N의 치명적인 결함은 N이 바뀌면 거의 모든 키의 목적지가 바뀐다는 것이다. 서버 하나가 빠졌을 뿐인데 캐시 전체가 무효화된다.
  • 서버들에 부하를 분산하기 위해 해시 함수를 쓸 수 있다.
  • serverIndex = hash(key) % N 공식으로 어떤 서버에 접근할지 결정한다.
  • 이 방식은 서버 풀의 크기가 고정되어 있고 데이터 분포가 균등할 때는 잘 동작한다.
  • 하지만 N대 중 1대에 장애가 나면 나머지 연산의 인덱스 값이 전부 달라진다.
  • 결과적으로 대규모 캐시 미스가 발생한다.

캐시 미스의 연쇄

대부분의 키가 엉뚱한 서버를 가리키게 되면, 그 서버들은 전부 캐시 미스를 내고 DB로 내려간다. 서버 한 대가 죽은 사고가 DB 전체가 무너지는 사고로 번지는 전형적인 경로다.

정리

  • hash(key) % N은 N이 고정일 때만 쓸 만하다.
  • N이 하나 바뀌면 거의 모든 키가 재배치된다.
  • 결과는 대규모 캐시 미스 → DB 폭주.
5-2

안정 해시

키와 서버를 같은 링 위에 올려놓으면, 서버가 바뀌어도 이웃만 영향을 받는다.

핵심 안정 해시의 발상은 키의 목적지를 계산하지 말고 탐색하게 만드는 것이다. 계산식에 N이 들어가지 않으므로 N이 바뀌어도 대부분의 키는 제자리에 남는다.
  • 테이블 크기가 조정될 때 평균적으로 k/n 개의 키만 재배치하는 해시 기술이다. (k = 키의 개수, n = 슬롯의 개수)
  • 이와 달리 전통적인 해시 테이블은 슬롯 수가 바뀌면 거의 모든 키를 재배치한다.

해시 공간과 해시 링

  • 해시 함수로 SHA-1을 쓴다고 가정한다.
  • SHA-1의 해시 공간 범위는 0 ~ 2160 − 1이다.
  • 이 선분의 양 끝을 이어 붙이면 해시 링이 된다.

해시 서버

  • 해시 함수 f를 쓰면 서버의 IP나 이름을 링 위의 어떤 위치에 대응시킬 수 있다.

해시 키

  • 여기서 쓰는 해시 키는 나머지 연산을 쓰지 않는다. 이 점이 앞 절과의 결정적인 차이다.
  • 키 역시 링 위 어느 지점에 배치된다.

서버 조회

  • 어떤 키가 저장되는 서버는, 그 키의 위치에서 시계 방향으로 링을 탐색하다 만나는 첫 번째 서버다.
키는 자기 오른쪽의 첫 서버에 배정된다 — 계산식이 아니라 위치 관계가 배정을 정하므로, 서버 목록이 바뀌어도 대부분의 키는 같은 이웃을 만난다.

서버 추가

  • 서버를 추가하더라도 키 가운데 일부만 재배치하면 된다.
  • 기존에 k0 → s0였다면, s4가 k0과 s0 사이에 추가되는 순간 k0은 s4에 저장된다. 나머지 키는 그대로다.

서버 제거

  • 서버 하나가 제거되어도 추가와 마찬가지로 일부만 재배치된다.
  • s1이 삭제되면 s1이 갖고 있던 k1이 다음 서버인 s2로 옮겨 간다. 그 밖의 키는 영향을 받지 않는다.

추가든 제거든 영향 범위는 그 서버가 맞닿은 구간뿐 — 나머지 키들은 목적지가 그대로다. 이것이 k/n의 의미다.

안정 해시의 기본 절차

  1. 서버와 키를 링에 배치한다

    균등 분포 해시 함수를 써서 서버와 키 모두를 같은 해시 링 위에 올린다.

  2. 시계 방향으로 탐색한다

    키 위치에서 시계 방향으로 링을 돌다 만나는 최초의 서버가 그 키가 저장될 서버다.

기본 절차에서 발생하는 두 가지 문제

  • 파티션(인접한 서버 사이의 해시 공간)의 크기를 균등하게 유지하는 것이 불가능하다. 어떤 서버는 작은 해시 공간을, 어떤 서버는 큰 공간을 할당받는다.
  • 따라서 키의 균등한 분포를 달성하기가 어렵다.
  • 이 두 문제는 가상 노드로 해결한다.
같은 서버 3대인데 부하는 완전히 다르다 — 왼쪽은 링 위에 서버가 3점만 찍혀 있고, 오른쪽은 각 서버가 여러 점으로 흩어져 있다.

가상 노드

  • 실제 노드(서버)를 가리키는 노드로, 서버 하나가 링 위에 여러 개의 가상 노드를 가질 수 있다.
  • 각 서버는 하나가 아닌 여러 개의 파티션을 관리하게 된다.
  • 탐색 방식은 같다. 링을 돌다 만나는 최초의 가상 노드가 가리키는 서버가 그 키의 저장소다.
  • 가상 노드 수를 늘리면 키 분포는 점점 균등해지지만, 그만큼 저장 공간이 더 필요하다.
  • 이 부분은 시스템 요구사항에 맞춰 적절한 트레이드오프가 필요하다.

재배치할 키 결정

  • 서버가 추가되거나 제거되면 데이터 일부는 재배치가 필요하다.
  • 삭제된 서버의 다음 서버가 그 키들을 넘겨받는다.

안정 해시가 실제로 쓰이는 곳 보강

아마존 DynamoDB의 파티셔닝, 아파치 Cassandra의 클러스터 파티셔닝, Discord의 채팅 애플리케이션, Akamai CDN, Maglev 네트워크 부하 분산기가 모두 안정 해시를 쓴다. 이 책 안에서도 6장 키-값 저장소의 데이터 파티션과 9장 다운로더 서버 부하 분산에서 다시 등장한다.

정리

  • 안정 해시는 슬롯 수가 바뀔 때 평균 k/n 개의 키만 재배치한다.
  • 키는 링 위에서 시계 방향으로 만나는 첫 서버에 배정된다.
  • 순진한 구현은 파티션 크기가 불균등하다는 문제가 있고, 가상 노드가 이를 해결한다.
  • 가상 노드 수는 분포 균등성과 저장 공간 사이의 트레이드오프다.
