서버 설정

MySQL의 동작은 570여 개의 시스템 변수가 결정한다. 어디에 적히고 언제 반영되는지가 첫 관문이다.

핵심 시스템 변수는 범위(글로벌/세션) 와 변경 시점(동적/정적) 두 축으로 나뉜다. 8.0의 SET PERSIST 는 이 중 "지금 반영"과 "재시작 후에도 유지"를 한 번에 해결한 명령이다.

설정 파일은 하나뿐이다

MySQL 서버는 단 하나의 설정 파일만 사용한다. 유닉스 계열은 my.cnf, 윈도우는 my.ini 다. 정해진 여러 디렉터리를 순서대로 탐색하다가 처음 발견한 파일을 쓴다.

terminal 
$ mysqld --verbose --help | grep my.cnf
/etc/my.cnf /etc/mysql/my.cnf /usr/local/mysql/etc/my.cnf ~/.my.cnf
                      my.cnf, $MYSQL_TCP_PORT, /etc/services, built-in default

탐색 순서가 곧 우선순위다. /etc/my.cnf 가 있으면 ~/.my.cnf 는 쳐다보지도 않는다는 뜻이라, "설정을 바꿨는데 안 먹는다"의 절반은 여기서 나온다.

설정 파일 구성

하나의 파일 안에 여러 프로그램의 설정을 담을 수 있고, 실행 프로그램 이름이 그대로 그룹명이 된다.

my.cnf 
[mysqld]
port = 3306

[mysql]
default-character-set = utf8mb4

[mysqld] 는 서버 데몬이, [mysql] 은 CLI 클라이언트가 읽는다. 서버 설정을 [mysql] 밑에 적어두면 아무 일도 일어나지 않는다.

시스템 변수의 특징

메모리 크기, 작동 방식 초기화, 사용자 제어 같은 값들이 전부 시스템 변수로 관리된다. SHOW VARIABLES / SHOW GLOBAL VARIABLES 로 확인할 수 있다.

매뉴얼의 시스템 변수 표는 다음 다섯 가지 속성을 갖는다.

속성의미
Cmd-Line명령행 인자로 값을 바꿀 수 있는가
Option File설정 파일로 제어할 수 있는가
System Var시스템 변수인가
Var Scope적용 범위 — 글로벌인가 세션당인가
Dynamic동적인가 정적인가 (재시작 필요 여부)

글로벌 변수와 세션 변수

글로벌 변수
  • 서버 인스턴스 전체에 영향을 미친다.
  • 주로 MySQL 서버 자체에 관련된 설정이다. (버퍼 풀 크기, 로그 파일 경로 등)
세션 변수
  • 클라이언트가 접속할 때 부여되는 옵션의 기본값을 제어한다.
  • 커넥션별로 다른 값을 지정할 수 있다.
  • 이미 연결된 커넥션의 세션 변수를 서버 쪽에서 바꿀 수는 없다.
flowchart LR
  A["SET GLOBAL"] --> B["글로벌 값 변경 (이후 새 커넥션에 적용)"]
  C["SET SESSION"] --> D["현재 커넥션에만 적용 (연결 끊기면 소멸)"]
  E["SET PERSIST"] --> B
  E --> F["mysqld-auto.cnf 에 기록 (재시작 후에도 유지)"]
  G["SET PERSIST_ONLY"] --> F
같은 SET 이지만 도달 범위가 다르다 — PERSIST 만이 "지금 반영"과 "재시작 후 유지"를 동시에 만족한다.

정적 변수와 동적 변수

  • 서버가 기동 중인 상태에서 변경할 수 있느냐로 동적/정적이 갈린다.
  • 정적 변수는 my.cnf 를 고쳐도 재시작하기 전까지 반영되지 않는다.
  • %...% 패턴으로 변수명을 검색할 수 있다.
mysql 
mysql> SHOW GLOBAL VARIABLES LIKE '%max%';

SET 으로 바꾼 값은 영속성이 없다. 현재 커넥션(또는 글로벌 메모리)에서만 유효하고 재시작하면 사라진다.

SET PERSIST

서버의 최대 커넥션 수를 급히 늘려야 하는 상황을 떠올려 보자. SET GLOBAL 로 바꾸면 즉시 반영되지만, 설정 파일에 따로 적어두지 않으면 재부팅하는 순간 초기값으로 돌아간다. 이 이중 작업을 8.0의 SET PERSIST 가 없앴다.

mysql 권장 
-- 즉시 반영 + 재시작 후에도 유지
SET PERSIST max_connections = 5000;

-- 설정 파일에만 기록 (정적 변수도 가능, 반영은 재시작 후)
SET PERSIST_ONLY innodb_page_size = 32768;
  • 영속화된 값은 my.cnf 가 아니라 데이터 디렉터리의 mysqld-auto.cnf 라는 별도 파일에 저장된다.
  • SET PERSIST_ONLY 는 정적 변수도 받아준다. 지금 반영은 안 되지만 파일에는 남는다.
  • 변경 이력은 performance_schema.variables_info 뷰에서 확인할 수 있다.
i

함께 알아두기 보강

mysqld-auto.cnf 는 my.cnf 보다 나중에 읽힌다. 즉 같은 변수가 양쪽에 있으면 mysqld-auto.cnf 쪽이 이긴다. my.cnf 를 아무리 고쳐도 값이 안 바뀐다면 예전에 누군가 SET PERSIST 를 쓴 것이다.

RESET PERSIST

SET PERSIST / SET PERSIST_ONLY 로 영속화한 변수를 되돌리는 명령이다. 파일을 직접 손대는 것보다 명령으로 처리하는 편이 장애를 예방한다 — 손으로 편집하다 문법이 깨지면 서버가 아예 뜨지 않는다.

my.cnf 파일

  • 8.0의 시스템 변수는 대략 570개 수준이다.
  • 인스턴스 스펙에 따라 오히려 성능을 떨어뜨리는 설정도 있다. 남의 my.cnf 를 그대로 복사하는 것이 위험한 이유다.

정리

  • 설정 파일은 하나만 쓰인다 — 탐색 경로 중 처음 찾은 파일이 전부다.
  • 변수는 글로벌/세션(범위) × 동적/정적(변경 시점)의 조합으로 이해한다.
  • SET 은 휘발성, SET PERSIST 는 즉시 반영 + 영속, SET PERSIST_ONLY 는 영속만.
  • 영속화된 값은 mysqld-auto.cnf 에 쌓이고 my.cnf 를 덮어쓴다. 되돌릴 땐 RESET PERSIST.
