18-1

Performance 스키마란

서버가 자기 자신에 대해 남기는 계측 데이터. 전부 메모리에만 있다.

핵심 Performance 스키마의 데이터는 재시작하면 전부 사라지고, 복제되지도 않는다. 장기 보관이 필요하면 따로 수집해야 한다.
  • 기본 제공되는 시스템 데이터베이스 중 하나로, 이름은 performance_schema 다.
  • 서버 내부 동작과 쿼리 처리에 관한 세부 정보가 저장된다.
  • 이 스키마의 모든 테이블은 PERFORMANCE_SCHEMA 스토리지 엔진이 처리한다.
  • 수집한 정보는 전부 메모리에 저장되고, 디스크에는 테이블 구조만 있다.
  • 서버가 재시작되면 모든 데이터가 초기화되고, 바이너리 로그에 기록되지 않아 레플리카로 복제되지 않는다.
i

이 성질이 의미하는 것 보강

"메모리에만 있고 복제되지 않는다"는 것은 두 가지를 뜻한다 — ① 서버마다 값이 다르다. 소스와 레플리카의 통계를 비교해도 의미가 없다. ② 장애 직후 재시작하면 원인 데이터가 사라진다. 그래서 모니터링 도구들이 이 값을 주기적으로 외부에 적재하는 것이다.

정리

  • 서버 내부 동작의 계측 데이터를 담는 시스템 DB 다.
  • 전부 메모리 에 있고 디스크에는 구조만 남는다.
  • 재시작하면 초기화되고 복제되지 않는다 — 서버별로 독립적인 값이다.
18-2

Performance 스키마 구성

크게 설정 테이블과 수집된 데이터 두 갈래.

핵심 setup_ 으로 시작하는 테이블이 설정, 나머지가 수집 결과다. 이 구분만 잡으면 100개가 넘는 테이블이 정리된다. 
flowchart LR
  A["setup_* 테이블 (무엇을 수집할지)"] --> B["수집 (Instrument)"]
  B --> C["events_* 테이블 (원시 이벤트)"]
  C --> D["*_summary_* 테이블 (집계 결과)"]
설정 → 수집 → 원시 이벤트 → 요약 의 흐름이다 — 실무에서는 대개 요약 테이블부터 본다.

Setup 테이블

  • 데이터 수집·저장과 관련된 설정 정보가 저장된다.
  • 이 테이블로 스키마 설정을 동적으로 변경할 수 있다.
mysql 
mysql> SHOW TABLES LIKE '%setup%';
+----------------------------------------+
| Tables_in_performance_schema (%setup%) |
+----------------------------------------+
| setup_actors                           |
| setup_consumers                        |
| setup_instruments                      |
| setup_meters                           |
| setup_metrics                          |
| setup_objects                          |
| setup_threads                          |
+----------------------------------------+

Instance 테이블

  • 데이터를 수집하는 대상, 즉 실체화된 객체(인스턴스) 에 대한 정보를 제공한다.
  • 인스턴스 종류별로 테이블이 나뉘어 있다.
mysql 
mysql> SHOW TABLES LIKE '%instance%';
+-------------------------------------------+
| Tables_in_performance_schema (%instance%) |
+-------------------------------------------+
| cond_instances                            |
| events_waits_summary_by_instance          |
| file_instances                            |
| file_summary_by_instance                  |
| mutex_instances                           |
| prepared_statements_instances             |
| rwlock_instances                          |
| socket_instances                          |
| socket_summary_by_instance                |
+-------------------------------------------+

Connection 테이블

생성된 커넥션들에 대한 통계와 속성 정보를 제공한다.

mysql> SHOW TABLES LIKE '%connection%';
+------------------------------------------------------+
| replication_asynchronous_connection_failover          |
| replication_asynchronous_connection_failover_managed  |
| replication_connection_configuration                  |
| replication_connection_status                         |
+------------------------------------------------------+

Variable 테이블

시스템 변수, 사용자 정의 변수, 상태 변수에 대한 정보를 제공한다.

mysql> SHOW TABLES LIKE '%variable%';
+-------------------------------------------+
| global_variables                          |
| persisted_variables                       |
| session_variables                         |
| user_variables_by_thread                  |
| variables_by_thread                       |
| variables_info                            |
+-------------------------------------------+

Event 테이블

네 종류의 이벤트 테이블로 나뉜다. 모두 스레드에서 실행된 쿼리 처리와 관련된 이벤트다.

이벤트확인할 수 있는 것
Wait 각 스레드가 대기 중인 이벤트. 일반적으로 락이나 I/O 때문에 대기한다
Stage 쿼리의 처리 단계. 구문 분석, 테이블 열기 등 현재 어느 단계인지와 단계별 소요 시간
Statement 실행된 쿼리 자체. 반환 레코드 수, 인덱스 사용 유무, 처리 방식 등
Transaction 실행된 트랜잭션. 종류, 상태, 격리 수준 등

Summary 테이블

  • 이벤트들을 특정 기준별로 집계한 요약 정보를 제공한다.
  • 이벤트 타입과 집계 기준별로 다양한 테이블이 있다.
mysql> SHOW TABLES LIKE '%summary%';
+------------------------------------------------------+
| events_errors_summary_by_account_by_error            |
| events_errors_summary_by_host_by_error               |
| events_errors_summary_by_thread_by_error             |
| events_errors_summary_by_user_by_error               |
| events_errors_summary_global_by_error                |
| events_stages_summary_by_account_by_event_name       |
| ...                                                  |
+------------------------------------------------------+

Lock 테이블

발생한 잠금과 관련된 정보를 제공한다.

mysql> SHOW TABLES LIKE '%lock%';
+---------------------------------------+
| data_lock_waits                       |
| data_locks                            |
| metadata_locks                        |
| rwlock_instances                      |
| table_lock_waits_summary_by_table     |
+---------------------------------------+

data_locks 와 data_lock_waits 가 레코드 잠금 분석의 출발점이다.

Replication 테이블

SHOW REPLICA STATUS 보다 훨씬 상세한 복제 정보를 제공한다.

mysql> SHOW TABLES LIKE '%replication%';
+------------------------------------------------------+
| replication_applier_configuration                    |
| replication_applier_filters                          |
| replication_applier_global_filters                   |
| replication_applier_status                           |
| replication_applier_status_by_coordinator            |
| replication_applier_status_by_worker                 |
| replication_asynchronous_connection_failover         |
| replication_asynchronous_connection_failover_managed |
| replication_connection_configuration                 |
| replication_connection_status                        |
| replication_group_member_stats                       |
| replication_group_members                            |
+------------------------------------------------------+

replication_applier_status_by_worker 는 멀티 스레드 복제의 워커별 상태를 보여 준다.

Clone 테이블

  • Clone 플러그인이 수행하는 복제 작업 정보를 제공한다.
  • 플러그인이 설치될 때 함께 생성되고, 삭제되면 함께 제거된다.

기타 테이블

error_log, host_cache 등 위 분류에 속하지 않는 나머지 테이블들이다.

정리

  • setup_* = 설정, 나머지 = 수집 결과.
  • 이벤트는 Wait · Stage · Statement · Transaction 네 종류.
  • 원시 이벤트보다 *_summary_* 테이블 을 먼저 보는 것이 실용적이다.
  • 잠금은 data_locks / data_lock_waits, 복제는 replication_*.
18-3

Performance 스키마 설정

생산자-소비자 구조 — 무엇을 수집할지(수집)와 어디에 담을지(저장)를 따로 설정한다.

핵심 상위 레벨이 꺼져 있으면 하위 레벨을 켜도 소용없다. 데이터가 안 쌓인다면 이 계층부터 확인해야 한다.

활성화

  • 5.6.6부터는 별도로 켜지 않아도 자동 활성화되어 있다.
  • 명시적으로 제어하려면 my.cnf 에 performance_schema = ON | OFF 를 설정한다.

메모리 사용량

모든 것이 메모리에 저장되므로, 저장되는 데이터 양이 곧 메모리 사용량과 직결된다.

데이터 수집 및 저장 설정

  • 생산자-소비자 방식으로 구현되어, 데이터를 수집하는 부분과 저장하는 부분이 나뉘어 동작한다.
  • 수집 쪽에서는 모니터링 대상과 수집 대상 이벤트를 설정할 수 있다.
  • 저장 쪽에서는 얼마나 상세하게 저장할지 레벨을 지정할 수 있다.
런타임 설정 적용
  • 런타임 설정은 Performance 스키마의 설정 테이블을 통해 이루어진다.
  • setup_ 접두사로 시작하는 테이블들이 설정 테이블이다.
저장 레벨 설정
  • 데이터 수집·저장에 가장 큰 영향을 미치는 설정이다.
  • 레벨이 아예 설정되지 않으면, 수집 대상에 포함되어 있어도 아무 데이터도 저장되지 않는다.
  • 상위 레벨이 비활성화되어 있으면 하위 레벨을 활성화해도 적용되지 않는다.
수집 대상 이벤트 설정
  • setup_instruments 테이블이 수집 대상 이벤트 목록을 담는다.
  • 이 테이블에 등록된 클래스의 인스턴스로부터만 데이터를 수집할 수 있다.
모니터링 대상 설정
  • setup_instruments 에 있는 이벤트를 전부 수집하는 것은 아니다.
  • 모니터링 대상과의 관련 여부를 확인하고, 관련이 있는 경우에만 그 설정을 고려해 수집한다.
  • setup_objects, setup_threads, setup_actors 로 모니터링할 대상을 설정한다.
설정 테이블설정 대상
setup_instruments무엇을 계측할 것인가 (이벤트 종류)
setup_consumers어디에 저장할 것인가 (저장 레벨)
setup_objects어떤 객체(스키마/테이블) 를 대상으로
setup_threads어떤 스레드 를 대상으로
setup_actors어떤 사용자·호스트 를 대상으로
설정의 영구 적용
  • 세션에서 설정한 내용은 재시작하면 전부 초기화된다.
  • my.cnf 같은 설정 파일에 기록해야 영구 적용된다.

정리

  • 5.6.6+ 는 기본 활성화. 모든 데이터는 메모리에 쌓인다.
  • 구조는 생산자(수집) - 소비자(저장). 설정도 두 갈래로 나뉜다.
  • setup_instruments(무엇을) + setup_consumers(어디에) + setup_objects/threads/actors(누구를).
  • 상위 레벨이 꺼져 있으면 하위는 무의미하다. 그리고 런타임 설정은 재시작하면 사라진다.
18-4

Sys 스키마란

Performance 스키마가 원재료라면, Sys 스키마는 조리된 접시다.

핵심 Sys 스키마는 새 데이터를 만들지 않는다. 이미 있는 데이터를 사람이 읽을 수 있게 가공할 뿐이다.
  • Performance 스키마의 어려운 사용법을 해결해 주는 솔루션이다.
  • Performance 스키마와 Information 스키마에 있는 데이터를 사용자가 쉽게 이해할 수 있는 형태로 출력하는 것이 목적이다.
  • 뷰, 스토어드 프로시저, 함수를 제공한다.

정리

  • Sys 스키마는 Performance / Information 스키마의 가공 레이어다.
  • 구성은 뷰 + 프로시저 + 함수.
18-5

Sys 스키마 사용을 위한 사전설정

전제조건은 단 하나 — Performance 스키마가 켜져 있을 것.

  • 기본적으로 Performance 스키마에 저장된 데이터를 참조한다.
  • 따라서 Sys 스키마를 제대로 쓰려면 Performance 스키마가 활성화되어 있어야 한다.
!

빈 결과가 나온다면

Sys 스키마의 뷰를 조회했는데 아무것도 안 나온다면, 십중팔구 원본인 Performance 스키마 쪽이 꺼져 있거나 해당 setup_* 설정이 비활성화되어 있는 것이다. Sys 스키마 자체를 의심할 필요는 없다.

정리

  • Sys 스키마는 Performance 스키마 없이는 아무 값도 보여 주지 못한다.
18-6

Sys 스키마 구성

테이블 하나, 그리고 두 종류의 뷰.

핵심 x$ 접두사가 붙은 뷰는 가공되지 않은 원본 값이다. 사람이 볼 때는 접두사 없는 쪽, 도구가 파싱할 때는 x$ 쪽을 쓴다.

Sys 스키마는 테이블, 뷰, 프로시저, 함수로 구성된다.

테이블

  • Sys 스키마의 DB 객체들이 쓰는 옵션 정보가 저장되는 테이블로, 하나만 존재한다.
  • InnoDB 스토리지 엔진으로 되어 있어 데이터가 영구 보존된다.

뷰

종류이름 규칙출력용도
Formatted-View 접두사 없음 사람이 읽기 쉬운 수치로 변환해서 보여 준다 (예: 1.23 s) 사람이 직접 볼 때
Raw-View x$ 접두사 저장된 원본 형태 그대로 출력한다 (예: 1230000000000) 도구가 파싱하거나 계산할 때

스토어드 프로시저

  • Performance 스키마의 설정을 쉽게 확인하고 변경할 수 있게 해 준다.
  • 서버 상태와 실행 중인 쿼리들을 종합 분석한 보고서 형태의 데이터도 확인할 수 있다.

함수

Performance 스키마의 설정과 데이터를 조회하는 등 다양한 기능을 제공한다.

정리

  • 구성 — 설정 테이블 1개 + 뷰 + 프로시저 + 함수.
  • 뷰는 Formatted(사람용)와 x$ Raw(기계용) 두 벌로 제공된다.

이 절은 학습하지 않았다
