12-1

전문 검색

한글에는 n-gram. 형태소 분석에 들일 노력 대비 효과가 가장 확실한 선택지다.

핵심 ngram_token_size 는 인덱스 생성 후에 바꾸면 안 된다. 그리고 그보다 짧은 검색어로는 아무것도 찾을 수 없다.

왜 n-gram 인가

  • 단어를 분리해 형태소를 찾고 그것을 인덱싱하는 방식은 서구권 언어에는 적합하지만 한글·중국어에는 맞지 않는다.
  • 대안으로 형태소나 어원과 무관하게 토큰 기반으로 인덱싱하는 n-gram 파서가 도입되었다.
  • 한글은 형태소 분석만 해도 엄청난 노력과 시간이 드므로, n-gram 검색이 한글 문서에 매우 유용하다.

전문 검색 인덱스의 생성과 검색

  • 형태소 분석(서구권은 어근 분석) 또는 n-gram 파서로 인덱싱할 토큰을 분리한다.
  • MySQL은 기본적으로 공백 같은 띄어쓰기 기준으로 토큰을 나눠 인덱싱한다.
  • ngram_token_size 로 토큰 길이를 제어하며 1~10 까지 설정 가능하다. 보통 2~3 이 적합하다.
    • 길이에 따라 bi-gram(2), tri-gram(3) 이라고 부른다.
    • 인덱스 생성 이후에는 이 값을 바꾸면 안 된다. 바꾸면 서버를 재시작해야 반영되고, 기존 인덱스와 불일치가 생긴다.
  • n-gram 크기보다 짧은 검색어로는 결과가 나오지 않는다. bi-gram 이면 1글자 검색은 아무것도 못 찾는다.
  • 검색 쿼리가 들어오면 검색어도 인덱싱할 때와 같은 방식으로 토큰을 잘라 낸다.
bi-gram 전문 검색 테이블 
CREATE TABLE tb_bi_gram (
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(100),
  body TEXT,
  FULLTEXT INDEX fx_msg(title, body) WITH PARSER ngram
);

-- 2글자 이상이어야 검색된다
SELECT * FROM tb_bi_gram
WHERE MATCH(title, body) AGAINST ('word' IN BOOLEAN MODE);

전문 검색 쿼리 모드

자연어 검색과 불리언 검색 두 가지를 지원한다. 지정하지 않으면 자연어 검색이 쓰인다.

테스트 데이터
INSERT INTO tb_bi_gram VALUES
  (NULL, 'Oracle',         'Oracle is database'),
  (NULL, 'Mysql',          'Mysql is database'),
  (NULL, 'Mysql article',  'Mysql is best open source database'),
  (NULL, 'Oracle article', 'Oracle is best commercial database'),
  (NULL, 'Mysql manual',   'Mysql manual is true guide for mysql');
자연어 검색 (Natural Language Mode)
  • 검색어에 제시된 단어를 많이 가진 순서대로 정렬해 결과를 반환한다.
  • 검색어가 문장이면 공백·개행으로 분리한 뒤 다시 토큰을 만들어 일치율을 계산한다.
  • ., , 같은 문장 부호는 모두 무시된다.
SELECT id, title, body,
  MATCH(title, body) AGAINST ('MySQL' IN NATURAL LANGUAGE MODE) AS score
FROM tb_bi_gram
WHERE MATCH(title, body) AGAINST ('MySQL' IN NATURAL LANGUAGE MODE);
idtitlebodyscore
5Mysql manualMysql manual is true guide for mysql0.5906
2MysqlMysql is database0.3937
3Mysql articleMysql is best open source database0.3937

id 5는 mysql 이 두 번 등장해 점수가 가장 높다. 이 score 를 ORDER BY 에 쓰면 관련도순 정렬이 된다.

불리언 검색 (Boolean Mode)
  • 자연어 검색은 단어 존재 여부만 보지만, 불리언 검색은 논리 연산이 가능하다.
  • + — 반드시 포함되어야 한다.
  • - — 포함되지 않아야 한다.
  • 아무 기호도 없으면 포함된 단어 중 하나라도 있으면 일치로 본다.
  • "..." 로 묶으면 공백과 무관하게 하나의 단어처럼 취급된다.
  • mysql* 같은 와일드카드 패턴도 지원하지만, 이미 2글자 토큰으로 검색되므로 굳이 쓸 필요는 없다.
SELECT id, title, body,
  MATCH(title, body) AGAINST ('+Mysql -manual' IN BOOLEAN MODE) AS score
FROM tb_bi_gram
WHERE MATCH(title, body) AGAINST ('+Mysql -manual' IN BOOLEAN MODE);
idtitlebodyscore
2MysqlMysql is database0.3937
3Mysql articleMysql is best open source database0.3937

-manual 때문에 아까 1위였던 id 5가 결과에서 사라졌다.

검색어 확장 (Query Expansion)
  • 1차 검색 결과에서 공통으로 발견되는 단어를 모아 한 번 더 검색하는 방식이다.
  • 단점 — 사용자가 딱 원하는 데이터만 가져올 수 없고, 전문 검색 쿼리를 불필요하게 많이 실행할 수 있다.
SELECT * FROM tb_bi_gram
WHERE MATCH(title, body) AGAINST('database' WITH QUERY EXPANSION);

database 하나로 검색했는데 5건 전부가 나온다 — 1차 결과에 공통으로 있던 is, best 같은 단어까지 2차 검색에 동원되기 때문이다.

전문 검색 인덱스 디버깅

  • 전문 검색은 원본 값을 그대로 인덱싱하지 않고 가공하므로 오류의 원인을 찾기 어렵다.
  • innodb_ft_aux_table 을 지정하면 information_schema 에서 인덱스의 실제 내부를 들여다볼 수 있다.
전문 검색 인덱스 내부 들여다보기 
SET GLOBAL innodb_ft_aux_table = 'realmysql/tb_bi_gram';

-- 전문 검색 인덱스의 설정 내용
SELECT * FROM information_schema.innodb_ft_config;

-- 인덱스가 가진 엔트리 목록
-- 각 토큰이 어떤 레코드에 몇 번, 어느 위치에 쓰였는지 알려 준다
SELECT * FROM information_schema.innodb_ft_index_table;

-- 새 레코드는 바로 디스크가 아니라 캐시에 쌓였다가 일괄 저장된다
-- (캐시 크기는 innodb_ft_cache_size)
-- 여기서 실제로 어떻게 토크나이징 되었는지 볼 수 있다
SELECT * FROM information_schema.innodb_ft_index_cache;

-- 삭제된 레코드
SELECT * FROM information_schema.innodb_ft_deleted;

-- 현재 인덱스에서 삭제가 진행 중인 레코드
SELECT * FROM information_schema.innodb_ft_being_deleted;
i

"왜 안 찾아지지?" 를 푸는 순서 보강

① innodb_ft_index_cache 를 먼저 본다 — 방금 넣은 레코드가 아직 캐시에 있을 수 있다. ② 거기에 내가 기대한 토큰이 실제로 있는지 확인한다. ③ 없다면 불용어로 걸러졌거나 ngram_token_size 보다 짧은 것이다. 이 세 단계면 대부분의 "전문 검색이 안 된다" 는 풀린다.

정리

  • 한글 전문 검색은 n-gram(WITH PARSER ngram) 이 현실적인 답이다.
  • ngram_token_size 는 인덱스 생성 전에 확정하고, 그보다 짧은 검색어는 못 찾는다는 점을 전제로 설계한다.
  • 모드는 자연어(관련도 점수) / 불리언(+, -, "...") / 검색어 확장 세 가지.
  • 디버깅은 innodb_ft_aux_table + information_schema.innodb_ft_* 로 인덱스 내부를 직접 확인한다.
