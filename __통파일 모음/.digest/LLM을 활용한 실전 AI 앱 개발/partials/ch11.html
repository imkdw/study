11-1

검색 성능을 높이기 위한 두 가지 방법

넓게 건지고 정밀하게 다시 줄 세운다.

핵심 검색 성능을 올리는 길은 둘이다 — 교차 인코더로 순위를 다시 매기거나, 바이 인코더를 내 데이터로 학습시키거나.

바이 인코더의 위치

  • 바이 인코더는 입력 문장에 대해 독립적인 문장 임베딩을 생성한다.
  • 임베딩끼리는 코사인 유사도 같은 가벼운 거리 계산으로 비교하므로, 큰 데이터셋에서도 빠르게 가장 비슷한 문장을 찾을 수 있다.
  • 이 특성 때문에 바이 인코더는 문장 임베딩 생성의 대표 방식이자 RAG 의 필수 구성요소로 쓰인다.

방법 ① 순위 재정렬

교차 인코더로 1차 검색에서 걸러진 문장들의 유사도를 다시 계산해 순서를 바꾸는 것을 순위 재정렬(reranking)이라 한다.

  1. 바이 인코더가 넓게 건진다

    대규모 문서에서 검색 쿼리와 유사한 소수의 후보를 선별한다. 수백만 건에서 수십 건으로 줄인다.

  2. 교차 인코더가 정밀하게 줄 세운다

    선별된 후보에 대해서만 쿼리와 함께 넣고 유사도를 계산해 유사한 순서대로 재정렬한다.

i

왜 이 순서가 성립하나 보강

바이 인코더는 재현율(정답을 후보 안에 포함시키는 능력)이 좋고, 교차 인코더는 정밀도(후보 중 정답을 위로 올리는 능력)가 좋다. 1차에서 정답을 놓치면 2차가 아무리 정확해도 복구할 수 없으므로, 1차는 top_k 를 넉넉히 잡아 재현율을 확보하는 것이 원칙이다.

방법 ② 내 데이터로 추가 학습

문장 임베딩 모델도 다른 딥러닝 모델과 마찬가지로 학습 데이터와 유사한 입력에 더 잘 작동한다. 따라서 실제로 사용하려는 데이터셋으로 추가 학습하면 검색 성능을 높일 수 있다. 다음 두 절이 이 방법을 다룬다.

정리

  • 바이 인코더는 빠르고 확장 가능해 RAG 의 1차 검색을 담당한다.
  • 순위 재정렬: 바이 인코더로 후보를 좁히고 교차 인코더로 다시 줄 세운다.
  • 미세 조정: 사용할 데이터셋으로 임베딩 모델을 추가 학습한다.
  • 1차 검색은 재현율, 2차 재정렬은 정밀도를 담당한다.
11-2

언어 모델을 임베딩 모델로 만들기

사전 학습 모델을 그냥 쓰면 0.36, 학습시키면 0.90.

핵심 언어 모델을 그대로 평균 풀링해서 쓰면 문장 임베딩 모델로서는 형편없다(0.36). 유사도 라벨이 있는 데이터로 학습시켜야 비로소 쓸 만해진다(0.90).

사전 학습된 언어 모델로 임베딩 모델 만들기

10-2 에서 본 것처럼 트랜스포머 층 + 풀링 층을 이어 붙이면 형태상으로는 문장 임베딩 모델이 된다.

build_model.py 
from sentence_transformers import SentenceTransformer, models

# 사용할 언어 모델 로드
transformer_model = models.Transformer('klue/roberta-base')

# 출력 토큰들을 평균 내는 평균 모드로 풀링 층 구성
pooling_layer = models.Pooling(
    transformer_model.get_word_embedding_dimension(),
    pooling_mode_mean_tokens=True,
)

# 두 모듈을 결합해 문장 임베딩 모델 생성
embedding_model = SentenceTransformer(modules=[transformer_model, pooling_layer])

실습 데이터셋 — KLUE STS

STS(Semantic Textual Similarity)는 두 문장이 얼마나 유사한지를 점수로 라벨링한 데이터셋이다. 임베딩 모델 학습에 딱 맞는 형태다.

학습 데이터에서 검증 데이터 분리
split.py 
# 학습 데이터의 10% 를 학습 진행 확인용 검증 데이터로 분리
klue_sts_train = load_dataset('klue', 'sts', split='train') \
    .train_test_split(test_size=0.1, seed=42)
klue_sts_train, klue_sts_eval = klue_sts_train['train'], klue_sts_train['test']
라벨 정규화

원본 라벨은 0~5 척도인데, 코사인 유사도의 목표값으로 쓰려면 0~1 로 맞춰야 한다. 그래서 5로 나눈다.

normalize.py 
from sentence_transformers import InputExample

def prepare_sts_examples(dataset):
    examples = []
    for data in dataset:
        examples.append(
            InputExample(
                texts=[data['sentence1'], data['sentence2']],
                label=data['labels']['label'] / 5.0,   # 0~5 → 0~1
            )
        )
    return examples

train_examples = prepare_sts_examples(klue_sts_train)
eval_examples  = prepare_sts_examples(klue_sts_eval)
test_examples  = prepare_sts_examples(klue_sts_test)
학습 전 성능 측정
baseline_eval.py 학습 전 
from torch.utils.data import DataLoader
from sentence_transformers.evaluation import EmbeddingSimilarityEvaluator

# 배치 데이터로더
train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=16)

# 검증/테스트용 평가 객체
eval_evaluator = EmbeddingSimilarityEvaluator.from_input_examples(eval_examples)
test_evaluator = EmbeddingSimilarityEvaluator.from_input_examples(test_examples)

print(test_evaluator(embedding_model))   # 0.36460670798564826
!

0.36 이 말하는 것

klue/roberta-base 는 한국어를 잘 이해하는 좋은 언어 모델이다. 그런데 문장 임베딩 모델로 쓰면 상관계수가 0.36 밖에 안 나온다. 토큰 임베딩을 평균 낸 벡터가 문장의 유사도를 반영하도록 학습된 적이 없기 때문이다. 언어를 이해하는 능력과 "의미가 가까우면 벡터도 가깝게" 만드는 능력은 별개다 — 이 격차를 메우는 것이 바로 다음 학습 단계다.

유사한 문장 데이터로 임베딩 모델 학습하기

CosineSimilarityLoss 는 두 문장을 임베딩으로 바꿔 코사인 유사도를 계산하고, 정답 유사도와의 차이를 줄이도록 학습시킨다.

train_embedding.py 학습 후 
from sentence_transformers import losses

num_epochs = 4
model_name = 'klue/roberta-base'
model_save_path = 'output/training_sts' + model_name.replace("/", "-")

# 코사인 유사도와 정답 유사도의 차이를 줄이도록 학습
train_loss = losses.CosineSimilarityLoss(model=embedding_model)

embedding_model.fit(
    train_objectives=[(train_dataloader, train_loss)],
    evaluator=eval_evaluator,
    epochs=num_epochs,
    evaluation_steps=1000,
    warmup_steps=100,
    output_path=model_save_path,
)

# 성능 평가
trained_embedding_model = SentenceTransformer(model_save_path)
print(test_evaluator(trained_embedding_model))   # 0.897121312312

KLUE STS 로 4 에포크 학습 후0.897
i

이 숫자가 뭘 재는 건가 보강

EmbeddingSimilarityEvaluator 가 반환하는 값은 모델이 계산한 코사인 유사도와 사람이 매긴 정답 유사도 사이의 상관계수다(기본은 스피어만 상관계수). 정확도가 아니라 순위 경향이 사람과 얼마나 일치하는가를 재는 지표이므로, 0.9 는 "모델이 매긴 유사도 순서가 사람의 판단과 거의 같다"는 뜻이다.

정리

  • 언어 모델 + 풀링 층 = 형태상 문장 임베딩 모델. 하지만 그대로는 성능이 낮다(0.36).
  • KLUE STS 처럼 유사도 라벨이 있는 데이터로 학습해야 쓸 만해진다(0.90).
  • 라벨은 코사인 유사도 범위에 맞춰 0~1 로 정규화한다.
  • CosineSimilarityLoss = 예측 코사인 유사도와 정답 유사도의 차이를 줄인다.
  • 평가 지표는 정확도가 아니라 사람 판단과의 상관계수다.
11-3

임베딩 모델 미세 조정하기

MNR 손실 — 정답 쌍만 모으면, 오답은 배치가 알아서 만들어준다.

핵심 MNR 손실은 같은 배치 안의 다른 문서를 자동으로 오답 취급한다. 덕분에 "관련 있는 쌍"만 모으면 되고, 오답 라벨링이 필요 없다.

임베딩 모델 성능 평가

MRC 데이터셋에는 질문-정답 본문 쌍만 있고 오답이 없다. 평가를 하려면 오답이 필요하므로, 다른 문서의 본문을 가져와 무관한 컨텍스트로 붙인다.

evaluate.py 
from sentence_transformers import SentenceTransformer, InputExample
from datasets import load_dataset
from sentence_transformers.evaluation import EmbeddingSimilarityEvaluator

# 질문과 관련 없는 임의의 본문을 컬럼으로 추가한다
def add_ir_context(df):
    irrelevant_contexts = []
    for idx, row in df.iterrows():
        title = row['title']
        # 제목이 다른 행에서 하나를 뽑아 무관한 컨텍스트로 사용
        irrelevant_contexts.append(
            df.query(f"title != '{title}'").sample(n=1)['context'].values[0]
        )
    df['irrelevant_context'] = irrelevant_contexts
    return df

klue_mrc_train = load_dataset('klue', 'mrc', split='train')
klue_mrc_test  = load_dataset('klue', 'mrc', split='validation')

df_train = klue_mrc_train.to_pandas()[['title', 'question', 'context']]
df_test  = klue_mrc_test.to_pandas()[['title', 'question', 'context']]

df_train_ir = add_ir_context(df_train)
df_test_ir  = add_ir_context(df_test)

sentence_model = SentenceTransformer('shangrilar/klue-roberta-base-klue')

examples = []
for idx, row in df_test_ir.iterrows():
    # 질문 - 정답 본문 → 라벨 1
    examples.append(InputExample(texts=[row['question'], row['context']], label=1))
    # 질문 - 무관한 본문 → 라벨 0
    examples.append(InputExample(texts=[row['question'], row['irrelevant_context']], label=0))

evaluator = EmbeddingSimilarityEvaluator.from_input_examples(examples)

print(evaluator(sentence_model))   # 0.815612312781
!

원문 교정 원문 교정

노트에서는 오답 쪽 컬럼명이 row['irrlevant_context'] 로 적혀 있었다. 앞서 add_ir_context 가 만든 컬럼명은 irrelevant_context 이므로 그대로 실행하면 KeyError 가 난다. 위 코드에서는 철자를 맞췄다.

i

왜 제목이 다른 행에서 뽑을까 보강

df.query(f"title != '{title}'") 로 같은 문서(제목)에서 온 본문을 제외한다. KLUE MRC 는 한 기사에 여러 질문이 달려 있어, 무작위로 뽑으면 사실상 정답인 본문이 오답으로 라벨링될 수 있다. 이런 거짓 오답(false negative)은 평가와 학습 모두를 망가뜨린다. 이 한 줄이 그것을 막는다.

MNR 손실로 미세 조정하기

  • MNR(Multiple Negatives Ranking) 손실은 MRC 처럼 서로 관련 있는 문장 쌍만 있는 데이터셋에 쓰기 좋다.
  • 하나의 배치 안에서 다른 데이터의 기사 본문을 관련 없는 데이터로 사용해 모델을 학습시킨다.
  • 즉 서로 관련 있는 데이터만으로 학습 데이터를 구성하면 된다.
배치가 클수록 오답이 제곱으로 늘어난다 — MNR 손실에서 배치 크기가 곧 학습 신호의 양인 이유다.
mnr_finetune.py 
from sentence_transformers import InputExample, losses, datasets

# 긍정(관련 있는) 쌍만으로 학습 데이터 구성
train_examples = []
for idx, row in df_train_ir.iterrows():
    train_examples.append(InputExample(texts=[row['question'], row['context']]))

# 한 배치 안에 같은 데이터가 중복되지 않도록 하는 데이터로더
batch_size = 16
loader = datasets.NoDuplicatesDataLoader(train_examples, batch_size)

# MNR 손실 함수
loss = losses.MultipleNegativesRankingLoss(sentence_model)

# MRC 데이터셋으로 미세 조정
epochs = 1
save_path = './klue_mrc_mnr'
sentence_model.fit(
    train_objectives=[(loader, loss)],
    epochs=epochs,
    warmup_steps=100,
    output_path=save_path,
    show_progress_bar=True,
)

print(evaluator(sentence_model))   # 0.8601021412321
!

원문 교정 원문 교정

노트에는 df_train_ir.interrows() 로 적혀 있는데 판다스의 메서드명은 iterrows() 다. 또 datasets.NoDuplicatesDataLoader 는 허깅페이스의 datasets 가 아니라 sentence_transformers.datasets 이므로, 두 라이브러리를 함께 쓸 때 이름이 충돌하지 않도록 import 를 명시해야 한다.

i

NoDuplicatesDataLoader 가 필요한 이유 보강

MNR 은 같은 배치의 다른 항목을 오답으로 간주한다. 그런데 배치 안에 같은 기사에서 나온 질문 두 개가 들어가면, 서로의 정답 본문이 오답으로 취급되어 모델에게 틀린 신호를 준다. 이 데이터로더가 배치 구성 단계에서 그런 중복을 막는다. 같은 이유로 MNR 학습에서는 배치 크기를 크게 잡을수록 유리하다 — 오답 후보가 늘어 학습 신호가 풍부해지기 때문이다.

단계테스트 상관계수
STS 로만 학습된 모델 (shangrilar/klue-roberta-base-klue)0.816
+ MRC 데이터로 MNR 미세 조정 (1 에포크)0.860

단 1 에포크로 0.816 → 0.860. 11-1 에서 말한 "사용하려는 데이터셋으로 추가 학습하면 검색 성능이 올라간다"가 숫자로 확인된 셈이다.

정리

  • 평가를 하려면 오답이 필요하다 — 제목이 다른 행에서 본문을 뽑아 무관한 컨텍스트를 만든다.
  • MNR 손실은 배치 안의 다른 항목을 자동으로 오답 취급한다 → 정답 쌍만 모으면 된다.
  • 그래서 배치 안 중복을 막는 NoDuplicatesDataLoader 가 필수이고, 배치가 클수록 유리하다.
