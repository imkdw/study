4-1

코딩 테스트 통과하기 — 사전 학습과 지도 미세 조정

다음 단어를 잘 맞히는 것과 사람 말을 잘 듣는 것은 다른 능력이다.

핵심 사전 학습과 지도 미세 조정은 학습 방식이 아니라 학습 데이터가 다르다. 둘 다 "다음 토큰 맞히기"를 하지만, 무엇으로 맞히기를 시키느냐가 모델의 성격을 바꾼다.

LLM 의 사전 학습

언어 모델은 결국 다음에 올 단어의 확률을 예측하는 모델이다. 학습할 때는 데이터의 일부를 입력으로 넣고 바로 다음에 나오는 정답 토큰을 맞히도록 시킨다. 이 과정을 방대한 텍스트에 대해 반복하면 모델은 어떤 맥락 뒤에 어떤 단어가 오는지를 익힌다.

다음 토큰 예측"]
  B --> C["기본 모델
언어는 안다"]
  D["지시-응답 데이터셋"] --> E["지도 미세 조정
다음 토큰 예측"]
  C --> E

학습 알고리즘은 두 단계가 같고, 먹이는 데이터만 다르다 — 그래서 지도 미세 조정도 인과적 언어 모델링이라 부른다.

지도 미세 조정

지도 미세 조정(SFT)은 모델이 요청의 형식을 해석하고, 응답의 형태를 갖춰 작성하고, 요청과 응답이 잘 연결되도록 추가로 학습시키는 단계다.

용어뜻
지도(supervised)학습 데이터에 정답(모범 응답)이 포함되어 있다는 의미
지시사항(instruction)사용자의 요구사항을 표현하는 문장
정렬(alignment)미세 조정을 통해 LLM 이 사용자 요청에 맞춰 응답하게 되는 것
인과적 언어 모델링앞의 토큰만 보고 다음 토큰을 예측하는 방식. 사전 학습과 SFT 가 공유한다

딥러닝 모델은 기본적으로 학습 데이터에 있는 행동을 배운다. 학습 데이터에 "요청에 응답하는" 형태의 데이터가 적으면 그 행동은 잘 배우지 못한다. 인터넷 텍스트를 그대로 먹인 기본 모델이 질문에 답하는 대신 질문을 이어서 써버리는 이유가 여기에 있다.

좋은 데이터셋이 갖춰야 할 조건

  • 지시 데이터셋의 지시사항이 다양한 형태일수록, 그리고 응답 데이터의 품질이 높을수록 정렬된 모델의 답변 품질이 높아진다.
  • 코드를 학습시킬 때도 교육적 가치가 높은 코드가 더 좋다. 주석이 잘 달려 있고 설명이 충실한 코드를 말한다.
  • 결국 데이터의 품질이 높으면 더 많은 양으로 학습할 때보다도 높은 성능에 도달할 수 있다.
i

함께 알아두기 보강

이 "양보다 질" 주장은 두 갈래 연구가 뒷받침한다. 마이크로소프트의 phi 계열은 교과서 수준의 합성 데이터로 훨씬 작은 모델이 큰 모델을 따라잡을 수 있음을 보였고, 메타의 LIMA 는 엄선된 1,000건의 지시-응답만으로도 상당한 정렬 성능이 나온다고 보고했다. SFT 단계는 새 지식을 넣는 단계가 아니라 이미 아는 것을 꺼내는 형식을 가르치는 단계에 가깝다는 관점이다.

정리

  • 사전 학습 = 대규모 텍스트로 다음 토큰 예측 → 언어를 아는 기본 모델.
  • 지도 미세 조정 = 지시-응답 데이터로 같은 방식 학습 → 요청에 답하는 모델. 이 과정을 정렬이라 한다.
  • 모델은 학습 데이터에 있는 행동만 배운다. 데이터에 없는 행동은 기대할 수 없다.
  • 지시사항의 다양성과 응답의 품질이 양보다 중요하다.
4-2

채점 모델로 코드 가독성 높이기

"이 코드 몇 점?"은 어렵지만 "둘 중 뭐가 나아?"는 쉽다.

핵심 절대 점수를 매긴 데이터셋은 만들기 어렵다. 그래서 둘 중 하나를 고르게 하는 선호 데이터셋을 만들고, 그걸로 점수를 매길 줄 아는 리워드 모델을 대신 학습시킨다.

선호 데이터셋

코드 A 와 B 를 비교해 더 가독성 높은 쪽을 선호 데이터, 선택되지 않은 쪽을 비선호 데이터로 분류한다. 이렇게 사람이 고른 쌍을 모은 것이 선호 데이터셋이다.

왜 코드 하나만 보고 점수를 매기지 않을까? 절대 점수를 일관되게 부여하는 것은 사람에게도 어렵기 때문이다. 평가자마다 기준이 다르고 같은 사람도 시점에 따라 흔들린다. 반면 두 코드를 나란히 놓고 나은 쪽을 고르는 일은 비교적 쉽고 일관적이다.

비선호
def sum_even(nums):
    even_sum = sum(n for n in nums if n % 2 == 0)
    return even_sum
선호
def sum_of_even_numbers(numbers_list):
    """
    Calculate the sum of all even numbers in a given list

    Params:
    numbers_list (list): A list of integers

    Returns:
    int: The sum of all even numbers in the list
    """
    even_numbers = [number for number in numbers_list if number % 2 == 0]
    total_sum = sum(even_numbers)
    return total_sum

이런 쌍을 모아 선호 데이터에 비선호 데이터보다 높은 점수를 주도록 채점 모델을 학습시킨다.

리워드 모델

  1. 여러 응답 생성

    지도 미세 조정을 마친 LLM 에 지시사항을 넣어 응답 A / B / C 를 미리 여러 개 만든다.

  2. 사람이 순위를 매김

    레이블러가 응답들을 비교해 순위를 정한다. 이 결과가 선호 데이터셋이 된다.

  3. 리워드 모델 학습

    선호 데이터셋으로 "이 응답은 몇 점짜리인가"를 출력하는 별도의 모델을 학습시킨다.

LLM 은 사용자의 요청에 맞춰 답을 주다 보니 차별적인 답변을 생성하는 등의 문제가 있었다. OpenAI 는 이를 제어하기 위해 생성한 답변의 점수를 평가하는 리워드 모델을 도입했다.

높은 코드 가독성 점수를 향해

강화 학습

강화 학습에서는 에이전트가 환경 안에서 행동을 하고, 그에 따라 상태가 바뀌며 보상이 발생한다. 에이전트는 더 많은 보상을 받도록 자신을 수정해 가며 학습한다.

RLHF — 사람의 피드백을 활용한 강화 학습

RLHF(Reinforcement Learning from Human Feedback)는 리워드 모델이 생성 텍스트를 평가해 점수를 매기고, 그 점수를 보상으로 삼아 언어 모델을 강화 학습으로 다듬는 방식이다. 강화 학습 관점에서 보면 토큰 하나를 생성하는 것이 하나의 행동이다. 다만 일반적인 강화 학습과 달리, 여기서는 전체 생성 결과에 대해 리워드 모델의 점수가 한 번 주어진다.

!

원문 교정 원문 교정

노트에는 이 약어가 RHLF 로 적혀 있는데 올바른 표기는 RLHF(Reinforcement Learning from Human Feedback)다. 이 정리본에서는 전부 RLHF 로 통일했다.

보상 해킹

보상만 높게 받으려는 편법이 생기는 현상을 보상 해킹(reward hacking)이라 한다. 평가 점수는 올라가지만 다른 능력이 깎이거나, 점수만 높게 받는 우회로가 만들어진다. 예를 들어 일부러 짧은 코드를 써서 "간결하니 가독성이 높다"고 판정받는 식이다.

PPO 의 핵심은 점선 화살표다 — 기준 모델에서 크게 벗어나지 못하게 묶어두면서 보상만 올린다.

PPO — 보상 해킹 피하기

PPO(Proximal Policy Optimization, 근접 정책 최적화)는 보상 해킹을 피하기 위해 쓴다. 지도 미세 조정 모델을 기준으로 삼고, 학습 중인 모델이 그 기준에서 너무 멀어지지 않는 가까운 범위 안에서 리워드 모델의 높은 점수를 찾도록 제한한다.

!

원문 교정 원문 교정

노트는 PPO 를 Proximal Preference Optimization 이라 풀어썼는데, 정확한 이름은 Proximal Policy Optimization 이다. 노트가 함께 적은 한국어 번역 "근접 정책 최적화"가 오히려 맞다. Preference 가 들어가는 쪽은 뒤에 나오는 DPO(Direct Preference Optimization)다 — 둘을 헷갈리기 쉽다.

RLHF, 멋지지만 피할 수 있다면

  • OpenAI 는 RLHF 로 편향성/공격성 등 AI 서비스에서 자주 문제되는 부분을 효과적으로 제어했다.
  • 하지만 결과물만큼이나 쓰기가 어렵다. 리워드 모델 학습 과정 자체가 까다롭고 비용도 많이 든다.
  • 그래서 최근에는 강화 학습도 리워드 모델도 쓰지 않고 사람의 선호를 학습하는 기술이 나왔다 — 다음 절의 DPO 다.

정리

  • 절대 점수 라벨링은 어렵고, 쌍 비교는 쉽다 → 선호 데이터셋.
  • 선호 데이터셋으로 리워드 모델을 학습시켜 점수를 자동화한다.
  • RLHF = 리워드 모델의 점수를 보상으로 삼는 강화 학습. 토큰 생성 하나가 행동이다.
  • 보상만 노리는 편법이 보상 해킹이고, 이를 막는 장치가 PPO(근접 정책 최적화)다.
  • RLHF 는 효과적이지만 비싸고 불안정하다는 게 다음 장으로 넘어가는 이유다.
4-3

강화 학습이 꼭 필요한가

기각 샘플링과 DPO — 강화 학습 없이 선호를 배우는 두 갈래.

핵심 DPO 는 리워드 모델도 강화 학습도 없이 선호 데이터셋으로 언어 모델을 직접 학습시킨다. RLHF 의 3단계 파이프라인이 1단계로 줄어든다.

기각 샘플링

지도 미세 조정을 마친 LLM 으로 여러 응답을 생성하고, 그중 리워드 모델이 가장 높은 점수를 준 응답만 모아 다시 지도 미세 조정을 수행한다. 강화 학습을 쓰지 않으니 학습이 비교적 안정적이고, 방법이 간단하고 직관적인데도 효과가 좋아 널리 쓰인다.

flowchart LR
  A["SFT 모델"] -->|"한 지시사항당
N개 생성"| B["응답 후보들"]
  B --> C["리워드 모델 채점"]
  C -->|"최고점만 남김"| D["새 SFT 데이터셋"]
  D -->|"다시 지도 미세 조정"| A
기각 샘플링은 강화 학습이 아니라 필터링이다 — 생성 → 채점 → 상위만 남겨 재학습하는 루프를 돈다.
메타가 밟은 순서
  1. 자기 지도 학습으로 사전 학습

    대용량 데이터로 다음 단어 예측(언어 모델링)을 수행해 기본 모델을 만든다.

  2. 선호 데이터셋 구축

    사람의 피드백을 반영한 선호 데이터셋을 만든다.

  3. 기각 샘플링으로 먼저 안정화

    바로 PPO 로 가지 않고, 기각 샘플링으로 더 빠르고 안정적으로 사람의 선호를 학습시킨다.

  4. 그 다음에 PPO

    어느 정도 정렬된 뒤에 강화 학습을 적용한다.

DPO — Direct Preference Optimization

RLHF 는 선호 데이터셋으로 리워드 모델을 만들고, 그 리워드 모델이 언어 모델의 출력을 평가하며 강화 학습을 돌린다. 반면 DPO 는 선호 데이터셋으로 언어 모델을 곧바로 학습시킨다.

리워드 모델필요불필요
강화 학습필요불필요
참고 모델SFT 모델 (KL 제약의 기준)SFT 모델 (학습 정도 비교의 기준)
학습 단계 수SFT → 리워드 모델 → 강화 학습SFT → 선호 학습

DPO 도 참고 모델(reference model)을 둔다. 학습하지 않는 학습 전 모델을 옆에 두고 비교하면서, 학습이 제대로 되고 있는지 — 그리고 원래 능력에서 지나치게 벗어나지 않는지 — 를 확인한다. 선호 학습에서 참고 모델로는 지도 미세 조정을 마친 모델을 쓰는 게 일반적이다.

✓

결론

DPO 로 학습하면 별도의 리워드 모델이 필요 없고 강화 학습도 쓰지 않는다. 선호 데이터셋 하나로 언어 모델을 바로 정렬하는 것이 DPO 의 전부다.

정리

  • 기각 샘플링: N개 생성 → 리워드 모델로 채점 → 최고점만 모아 재-SFT. 강화 학습 없이도 효과가 좋다.
  • 메타는 PPO 이전에 기각 샘플링을 먼저 돌려 안정적으로 선호를 학습시켰다.
  • DPO: 선호 데이터셋으로 언어 모델을 직접 학습. 리워드 모델도 강화 학습도 없다.
  • DPO 의 참고 모델은 보통 SFT 를 마친 모델이며, 학습 진행 상황을 비교하는 기준 역할을 한다.
