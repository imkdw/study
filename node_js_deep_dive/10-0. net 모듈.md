## Server.socket과 Client.socket의 차이점

- 서버의 소켓은 서버 프로세스 메모리에 만들어진 통신 창구이자 파일
- 클라이언트의 소켓은 클라이언트 프로세스 메모리에 만들어진 별개의 통신 창구이자 피일
- Loopback을 쓰는 환경에서는 하나의 컴퓨터 내부에 존재하지만 본질적으론 전혀 다른 두 개의 독립적인 문임
- 이처럼 두 개의 독립적인 파일이 네트워크라는 보이지 않는 양 끝단에서 듀플렉스 스트림을 형성함

```ts
import net from "node:net";

const server = net.createServer((socket) => {
  socket.on("data", (data) => {
    console.log("Receieving From Client Data: ", data);
  });
});

server.listen(7777, "127.0.0.1", () => {
  console.log("Server Listening Port on: ", server.address());
});
```

```ts
import net from "node:net";

const socket = net.createConnection({ host: "127.0.0.1", port: 7777 }, () => {
  const buff = Buffer.from("node");

  /**
   * 4바이트(node)의 데이터를 OS의 전송계층으로 넘겨서 패킷으로 만듦
   * 이후에 목적지로 만들라고 명령함
   */
  socket.write(buff);
});
```

- 루프백을 사용하며 포트가 7777인 패킷만 캡쳐하기 위해서 `ip.addr == 127.0.0.1 && tcp.port == 7777` 필터를 적용

### 연결 수립 단계

- SYN, ACK를 주고받으며 연결을 요청하고 수락하는 단계
- 통신의 시작을 위한 서로 준비 상태를 확인하고는 연결 과정임

### 실제 데이터 전송

- `Len=4`는 4바이트의 패킷을 의미함. 위 코드에서 `node`를 전송해서 4바이트라고 나옴

## 4바이트를 보냈지만 크기가 엄청나게 커지는 이유

- OS의 응용 계층에서 4바이트의 데이터를 전송하지만 실제 패킷의 크기는 50~60 바이트로 매우 커짐
- 이는 전송 게층에서 TCP 헤더 20바이트를 부착 (포트 번호 기록)하고, 이후에 네트워크 계층에서 IP 프로토콜이 또 다시 20바이트짜리 부착함
- 이렇게 패킷을 만들고나서 이후에 데이터 계층에서는 최적화가 진행되는데 이 때 로컬에서는 루프백(로컬) 통신을 인지하고 이더넷 헤더를 붙이지 않음
- 실제 크기 자체는 OS마다 다르지만 계층들의 동작 방식은 동일함
