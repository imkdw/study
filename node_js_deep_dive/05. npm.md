## NPM (Node Package Manager)

- 전 세계 개발자들이 미리 만들어놓은 기능들을 가져다가 사용할 수 있는 저장 공간
- `npm init`을 통해서 프로젝트 공간을 만들고 `npm install`을 통해서 패키지 설치 가능
- yarn, pnpm 등 대체 패키지 매니저도 있는데 명령어 구조는 99% 일치하고 동작 방식은 npm과 동일함
- package.json에는 어떤 패키지를 설치하는지 나열함
- package-lock.json에는 패키지들의 버전에 대한 정보가 존재함
- 설치된 패키지의 원본 코드는 `node_modules` 폴더 내부에 저장됨. 이는 깃에 커밋하지 않아도 괜찮음

<br>

### 설치한 패키지 사용해보기

```ts
// npm install chalk
import chalk from "chalk";

console.log(chalk.blue("BLUE 로그"));
console.log(chalk.red.bold("RED 로그"));
console.log(chalk.green.bgWhite("하얀 배경의 초록색 로그"));
```

## NPM과 Git 협업, 버저닝

### node_modules

- npm에서 설치한 패키지들이 설치되는 폴더로 크게는 GB 단위로 올라감
- 이는 `.gitignore`에 등록해서 관리하고 이후 다른 개발자가 클론하거나 배포하면 다시 `npm i`로 설치하면됨

<br>

### 버전

- package.json 내부에서는 버전을 SemVer(유의적 버전)으로 관리함
- `^(캐럿)` 기능은 Minor, Patch 버전의 업데이트는 언제나 허용함
- `~(틸드)` 기능은 Patch 버전의 업데이트만 허용함
- 만약 호환성을 무시하고 최신버전을 사용하고 싶다면 `npm i chalk@latest` 형태로 설치함
- 특정 버전을 설치하고싶다면 `npm i chalk@4.1.2` 형태로 다운로드가 가능함

<br>

### package-lock.json

- 최초에 내가 설치했던 라이브러리 버전을 모든 버전정보를 명시해서 설치함
- 이를 통해서 어느곳에서 패키지를 설치해도 통일된 버전을 다운로드하므로 안전함
- 실무에서는 `npm ci`를 사용하는데 이는 기존 패키지를 모두 제거하고 package-lock.json 기준으로 새로운 node_modules를 만듦

<br>

## 개발용 의존성 devDependencies

- 일부 도구의 경우 실제 프로덕션에선 필요없고 오직 개발환경에서만 필요한 경우가 있음
- 이러한 패키지는 `npm i -D nodemon` 형태로 설치하며 package.json에는 devDependencies에 등록됨
- 종종 `script not found` 오류가 발생하는데 이런 상황에선 `npx nodemon app.js`형태로 실행하면됨
  - npx는 복잡한 환경변수나 경로 등 문제를 편하게 해결해주는 도구임

<br>

## 글로벌 패키지와 npx

- 일반적으로 `npm i`로 설치하면 특정 프로젝트에만 설치되며 그 내부에서만 동작함
- `npm i -g nodemon` 형태로 글로벌 패키지로 설치하면 어떤 프로젝트에서나 사용이 가능함
- 단점은 프로젝트의 package.json에 기록되지 않아서 다른 개발자가 `npm i`로 설치한 경우 문제가 발생함

<br>

### npx (Node Package Execute)

- 2026년 기준 `-g` 옵션을 강력하게 지양하고 있음
- npx는 아래처럼 동작하게됨
  - `npx nodemon app.js` 를 실행함
  - 만약 현재 내 프로젝트에 nodemon이 없다면 빠르게 npm에서 다운로드함
  - 이 때 임시 캐시폴더에 다운로드하며 이런 작업이 완료되면 모두 삭제함
  - 이후에는 캐시를 통해서 빠르게 로딩하고 실행이 가능하며 프로젝트간 버전 충돌을 차단해줌

<br>

## NPM 패키지 배포

- 내 코드를 NPM 저장소에 배포하는 방식으로 이렇게 배포하고나면 전 세계 개발자가 사용이 가능함
- 이 때 저장소에 올라가는 정보는 `package.json` 내부 프로퍼티에 의해서 입력됨
- `npm publish`를 통해서 배포가 가능한데 이미 배포된 버전은 절대 수정이 불가능함
- `npm version patch | minor | major` 명령어를 활용하면 간단하게 버전업이 가능함
