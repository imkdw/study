## Node.js에서 Stream과 Buffer

- 컴퓨터는 이미지, 텍스트 등 모든것을 0과 1로 해석함
- Node.js의 스트림이 다루는 데이터는 버퍼임. 아무리 복잡한 Json을 주고받아도 결국 0과 1임

<br>

## Writeable Stream

- 이름 그대로 데이터를 쓸 수 있는 스트림
- 해당 스트림에 데이터를 저장하면 내부 버퍼로 불리는 임시 저장소 성격의 내부 버퍼를 거침
  - 임시 버퍼는 16KB(16,384 Byte)의 비밀 공간인 버퍼가 존재
  - highWaterMark를 통해서 한계치를 직접 제어도 가능함
  - 데이터를 저장하면 먼저 내부 버퍼에 저장되며, 버퍼가 꽉 차면 시스템 콜이 발생하게됨
- 이후에 최종 목적지인 하드디스크나 외부 네트워크로 데이터를 흘려보냄
- `createWriteableStream`으로 생성하는 스트림은 단순히 텅 빈 파이프가 아님
- 내부에는 데이터의 흐름을 제어하는 메타데이터가 들어가는데 프로퍼티, 메서드, 이벤트가 존재함

<br>

### Properties

- 파이프의 현재 상태를 나타내는 속성값들을 의미함
- 파이프가 열려있는지(writeable), 내부에 얼마나 많은 데이터가 있는지(writeableLength) 등이 존재

<br>

### methods

- 스트림에게 직접 내리는 명령어나 함수를 뜻함
- 대표적으로 파이프에 데이터를 적재하는 write(), 파이프를 끝내는 end() 등이 존재함

<br>

### 이벤트

- 스트림이 특정 상태에 도달하면 알려주는 알림의 역할
- 내부 버퍼가 완전히 비워졌다고 알려주는 drain, 스트림이 닫혔다고 알려주는 close, 쓰기 도중 에러가 발생했다고 알려주는 error 등이 존재함

<br>

## Readable Stream

- 데이터를 읽어올 수 있는 스트림으로 Writeable Stream과는 정반대의 역할
- 10GB의 대용량 파일을 업로드하면 한번에 받아들이는게 아닌 내부 버퍼 크기만큼 잘게 쪼개서 읽어옴
- 일반적인 스트림 버퍼는 16KB, 데이터를 읽어올 때 버퍼는 64KB씩 안전하게 가져올 수 있음
- Readable 스트림은 내부의 이 크게 맞는 기본 버퍼를 가지고있고 여기도 다양한 속성이 존재함
- 웹브라우저를 통해 큰 크기의 영상이나 방대한 용량의 로그들을 서버에서 천천히 읽어서 분석하는 경우 필수적으로 쓰임

<br>

### methods

- 원할때 수동으로 데이터를 가져올 수 있는 read()
- 데이터가 너무 많이 가져와지는 경우 일시적으로 스트림을 멈추는 pause()
- pause()를 통해서 멈춘 스트림을 재개하는 resume() 등이 존재

<br>

### events

- data라는 이벤트는 내부 버퍼가 꽉 차게되는 경우 우리에게 주는 이벤트임
- 해당 이벤트가 발생하면 콜백함수를 통해서 화면에 출력하거나 이를 다른 스트림에 전달할 수 있음
- end 이벤트는 모든 스트림을 다 읽은 경우 발생하는 이벤트로 전체 데이터 흐름을 종료하는데 쓰임

<br>

## Duplex Stream

- Readable + Writeable이 결합된 하나의 스트림
- 통화를 예시로 양쪽에서 말하고 듣기가 가능한데 이 처럼 동시에 읽기/쓰기가 동시에 가능한 버퍼임
- 해당 스트림은 읽기 전용 버퍼와 쓰기 전용 버퍼를 각자 가지고있어서 서로 독립성을 가짐
- TCP 소켓 통신에서 클라이언트/서버가 동시에 연결된 상황에서 데이터를 주고 받을때 사용됨

<br>

## Transform Stream

- Duplex와 동일하게 양방향 스트림인데 중간에 변형 과정을 거칠 수 있음
- 통역사를 예시로 A로 부터 한국어를 듣고 영어로 해석해서 B에게 영어로 전달해주는것과 비슷함
- 해당 스트림을 통해서 실시간 암호화나 압축 등 처리가 가능함
