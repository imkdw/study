## HTTP

- L4 계층에 존재하는 프로토콜로 TCP / UDP 위에서 만들어진 더 상위레벨 통신 규약
- 통신을 진행하는 양측 컴퓨터간에 데이터를 어떻게 주고받을지 미리 정해놓은 규칙들임
- 언제, 어떻게, 어떤 모양으로 주고받을지 미리 정해놓을것을 프로토콜이라고 부름
- 일반 패킷통신과는 규모가 다른데 압도적으로 범용성이며 웹 생태계를 지탱하는 설계로 되어있음
- HTTP 자체는 서버-클라간 물리/논리적인 연결을 해주는게 절대 아님

<br>

## Node.js의 HTTP 모듈

- node:http로 불러와서 사용이 가능함
- V8 + libuv + llhttp 3개를 기반으로 동작하는 node.js 내장 모듈임

```ts
import http from "node:http";

const server = http.createServer();

const PORT = 7000;
server.listen(PORT, () => {
  console.log(`${PORT}에서 서버 열림`);
});
```

<br>

### HTTP 메시지

- 서버 / 클라이언트간 3way handshaking이 끝나면 서로 통신을 주고받을 수 있는 상태가됨
- 이 상태에서 교환되는 데이터를 HTTP 메시지라고 부름
- 메시지는 Octet Sequence라고 부르는데 약속된 형태를 띄고있는 데이터의 연속적인 흐름임

<br>

### Octet

- 네트워크 환경에서 정확히 8bit로 이루어진 데이터를 아주 엄격하게 부르는 전문 용어임
- 프로그래밍에서 흔히 말하는 1Byte랑 같은 의미임
- 즉 Octet Sequence는 1Byte 짜리 데이터들이 기차처럼 길게 이루어진 형태임
- 이 메시지의 목적은 양 끝단이 데이터를 동일하게 해석하기 위한 목적임
- 실제 데이터를 전송하면 이쁜 문자열이 아닌 컴퓨터가 이해 가능한 16진수 형태의 1바이트 조각 여러개가 전송됨

<br>

## 서버에 메시지 전송하기

### 서버

```ts
import http from "node:http";

const server = http.createServer();

const PORT = 7821;

server.listen(PORT, () => console.log(`${PORT}에서 서버 열림`));

server.on("request", (req, res) => {
  if (req.url === "/favicon.ico") {
    return;
  }

  console.log("--- METHOD ---");
  console.log(req.method);

  console.log("--- URL ---");
  console.log(req.url);

  console.log("--- HEADERS ---");
  console.log(req.headers);

  console.log("--- BODY ---");
  req.on("data", (chunk: Buffer) => console.log(chunk.toString("utf-8")));
});
```

<br>

### 클라

```ts
import http from "node:http";

/**
 * 에이전트를 생성하는 이유는 아래와 같음
 *
 * HTTP의 경우 단순한 프로토콜로 응용 계층의 텍스트일뿐 물리적인 전송 능력은 존재하지 않음
 * 데이터를 목적지까지 안전하게 보낼려면 하위 계층인 전송 계층인 TCP 소켓 생성 및 제어가 필요함
 * HTTP Agent는 이러한 골치 아픈 파이프라인을 전담해줌
 *
 * keepAlive를 통해서 3-way handshake로 맺어진 논리적인 연결을 유지하라고 지시함
 */
const agent = new http.Agent({ keepAlive: true });

const SERVER_HOST = "localhost";
const SERVER_PORT = 7821;

/**
 * http.request는 단순한 JS 객체가 아닌 Duplex Stream으로 구성되어있음
 *
 */
const request = http.request({
  agent,
  hostname: SERVER_HOST,
  port: SERVER_PORT,
  method: "POST",
  path: "/api/message",
  headers: { "content-type": "application/json" },
});

request.write(JSON.stringify({ message: "첫 번째 스트림 조각입니다." }));
request.write(JSON.stringify({ message: "두 번째 스트림 조각입니다." }));
request.write(JSON.stringify({ message: "세 번째 스트림 조각입니다." }));

/**
 * 데이터를 다 보냈으면 연결을 끝내야함
 * end 메서드는 데이터의 끝을 알리는 특수 신호인 0\r\n\r\n을 소켓으로 보냄
 * 서버에서는 특수 신호가 들어오면 데이터 수신을 멈추고 파싱을 진행하게됨
 */
request.end(JSON.stringify({ message: "마지막 전송 조각입니다." }));

/**
 * 요청 이후에 서버에서 응답이 온다면 response 이벤트가 발생함
 */
request.on("response", (response) => {
  console.log(response);
});
```

### 서버쪽 정보들

- `'transfer-encoding': 'chunked'`가 적힌 이유는 클라이언트에서 한번에 데이터를 밀어넣는게 아닌 계속해서 밀어넣는 방식을 사용함
- 만약 헤더에 정확한 `Content-Length`가 있다면 청크 전송 방식을 사용하지 않고 데이터를 한번에 깔끔한 데이터로 받음

### 정확한 바디의 길이를 전달하는 클라이언트

```ts
import http from "node:http";

const agent = new http.Agent({ keepAlive: true });

const SERVER_HOST = "localhost";
const SERVER_PORT = 7821;

const bodyData = JSON.stringify({ message: "모든 데이터를 한 번에 덩어리로 보냄" });

const byteLength = Buffer.byteLength(bodyData, "utf-8");

const request = http.request({
  agent,
  hostname: SERVER_HOST,
  port: SERVER_PORT,
  method: "POST",
  path: "/api/message",
  headers: {
    "content-type": "application/json",
    "content-length": byteLength,
  },
});

request.end(bodyData);
```

## Chunked 방식 vs 고정된 컨텐츠 길이

- 이는 UX 및 서버를 가르는 결정적인 선택임

<br>

### Content-Length

- 전체 바이트 크기를 정확하게 명확하면 수신측에서 전체 데이터의 규모를 미리 알 수 있음
- 파일 다운로드시 남은 시간이나 프로그레스바를 정확하게 표현이 가능해서 UX를 챙길 수 있음
- 하지만 전체 길이를 계산하기 위해서는 모든 데이터를 전부 메모리에 올려야함
- 영상 데이터나 실시간으로 생성되는 데이터의 경우는 OOM이 발생하거나 전송 자체를 못할수도 있어서 초기 응답이 느려짐
- 용량이 고정되어있고 한번에 읽기 쉬운 HTML/CSS 같은 정적 데이터를 다룰때 쓰면 좋음

<br>

### Chunked

- 전체 데이터의 크기를 몰라도 데이터가 생기는 즉시 바로 보낼 수 있어서 좋음
- OOM 위험이 없고 클라이언트에게 데이터의 첫 부분을 보여주는 시간이 매우 빠름
- 단점은 수신쪽에서 종료 신호를 주기 전까지는 언제 통신이 끝날지 예측이 불가능함
- 전체 크기를 모르니 진행률 표기도 불가능하고 그냥 돌아가는 프로그레스를 띄워야함
- 라이브 스트리밍이나 실시간으로 생성되는 거대한 데이터 리포트들을 다룰때 사용하면 좋음

<br>

## 2진수 버퍼로 변환되어 네트워크를 횡단하는 HTTP 통신

### 서버

```ts
import http from "node:http";

const server = http.createServer();

const PORT = 7821;

server.listen(PORT, () => console.log(`${PORT}에서 서버 열림`));

function parseStringHeader(req: http.IncomingMessage, property: string) {
  const raw = req.headers[property];
  if (typeof raw !== "string") {
    return "";
  }

  return raw;
}

server.on("request", (req, res) => {
  console.log("--- 헤더에서 추출한 커스텀 정보 ---");

  const authorName = decodeURIComponent(parseStringHeader(req, "name"));
  console.log(`작성자: ${authorName}`);

  /**
   * 쪼개서 들어오는 이진 버퍼 조각들 담을 임시 배열
   */
  const chunks: Buffer[] = [];

  /**
   * TCP 단편화 문제를 대비해서 들어온 데이터를 모두 이진 버퍼로 저장해놓음
   */
  req.on("data", (chunk: Buffer) => chunks.push(chunk));

  req.on("end", () => {
    const rawData = Buffer.concat(chunks).toString("utf-8");
    const parsedData = JSON.parse(rawData);

    res.writeHead(200, { "content-type": "application/json" });

    res.end(
      JSON.stringify({
        message: `제목이 '${parsedData.title}'인 포스트가 '${authorName}'님에 의해서 작성됨`,
      }),
    );
  });
});
```

<br>

### 클라

```ts
import http from "node:http";

const agent = new http.Agent({ keepAlive: true });

const SERVER_HOST = "localhost";
const SERVER_PORT = 7821;

const bodyData = JSON.stringify({ message: "모든 데이터를 한 번에 덩어리로 보냄" });

const request = http.request({
  agent,
  hostname: SERVER_HOST,
  port: SERVER_PORT,
  method: "POST",
  path: "/api/message",
  headers: {
    "content-type": "application/json",
    /**
     * 통신의 규칙을 정의하는 HTTP 헤더의 경우 ASCII 문자만 허용하도록 설계되어있음
     * 가변 멀티바이트 한글이나 이모지 같은걸 그냥 넣으면 실행 자체를 차단해버림
     */
    name: encodeURIComponent("우리동네코딩"),
  },
});

request.end(
  JSON.stringify({
    title: "1st 게시글",
    body: "본문임",
  }),
);

request.on("response", (res) => {
  console.log(`[HTTP ${res.statusCode}]`);
  console.log(res.headers);

  res.on("data", (chunk: Buffer) => {
    const rawData = chunk.toString("utf-8");
    console.log(JSON.parse(rawData));
  });
  res.on("end", () => console.log("전부 수신 완료"));
});
```

## HTTP 서버에 TCP 데이터를 전송하는 경우

- HTTP 모듈을 통해서 오픈된 서버는 깐깐한 검증을 거치는데 TCP의 경우 이러한 데이터를 보내지 않음
- 그래서 서버쪽에선 3-way handshaking 까지는 성공하지만 실제 데이터가 전달되진 않음

<br>

### 클라이언트

```ts
import net from "node:net";

/**
 * HTTP 서버에 순수 TCP 연결을 시도함
 */
const socket = net.createConnection({ host: "localhost", port: 7821 }, () => {
  console.log("서버와 TCP 연결이 성공적으로 수립되었습니다.");

  /**
   * V8 힙메모리가 아닌 컴퓨터의 물리적 Off Heap 메모리 공간에 4바이트 할당
   */
  const reqBuffer = Buffer.alloc(4);

  reqBuffer[0] = 99;
  reqBuffer[1] = 88;

  /**
   * 서버에 데이터 발송
   */
  socket.write(reqBuffer);
});

socket.on("data", (chunk: Buffer) => {
  console.log("--------- 수신된 서버 응답 ---------");
  console.log(chunk.toString("utf-8"));
  socket.destroy();
});

socket.on("end", () => {
  console.log("TCP 연결이 종료되었습니다.");
});
```
